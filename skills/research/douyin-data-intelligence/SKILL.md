# 抖音数据情报 Skill（Domestic Douyin Data Intelligence）

> 模仿 FastMoss 的数据驱动模式，但适配国内抖音环境。核心思路：**从公开/半公开渠道采集真实数据，用 FastMoss 的框架做结构化分析**。

## 核心原则

| 原则 | 说明 |
|------|------|
| **数据先行** | 先搜数据再出结论，不编造销量/GMV 数字 |
| **渠道可追溯** | 每个数据标注来源渠道，用户能自己复核 |
| **降级策略** | 付费数据拿不到就用地表数据，地表数据拿不到用推测区间 |
| **风控优先** | 电商数据很多是估算值，标注置信等级（高/中/低） |

## 数据采集渠道地图（按可靠性排序）

### 一级渠道（高置信度，优先使用）

| 渠道 | 可获取数据 | 使用方法 | 限制 |
|------|-----------|---------|------|
| **亿邦动力** (ebrun.com) | 月度抖音商品/品牌热卖榜，有明确销售额区间 | web_search + web_extract | 仅月度，品类有限 |
| **中外玩具网** (ctoy.com.cn) | 抖音玩具月销榜，有月销售额/销量区间 | web_search + web_extract | 仅玩具品类；有WAF/堡垒云CAPTCHA防护，自动访问会触发滑块验证 |
| **电商在线/天下网商** | 电商行业分析，含抖音大促数据 | web_search | 不定期 |
| **抖音电商公众号** | 官方类目排行榜、新品榜 | web_search | 不定期发布 |
| **1688** (1688.com) | 供应链价格、起批量、热销指数 | web_search + web_extract | 非直接抖音销量，但可交叉验证 |
| **知乎/小红书** | 用户口碑、测评反馈 | agent-reach 或 web_search | 定性数据，非定量 |
| **互联岛/电商战报网** (vvvvvv.com) | 抖音商品销量榜、达人榜、小店榜，按类目（日用百货/玩具/母婴等）+时段（日/周/月）分类 | 见下方 `computer_use` 方案 | 需用户登录；Nuxt SPA渲染，curl不可用；子域名：goods.vvvvvv.com（商品）、shop.vvvvvv.com（小店） |

### 二级渠道（中等置信度，需交叉验证）

| 渠道 | 可获取数据 | 使用方法 | 限制 |
|------|-----------|---------|------|
| **蝉妈妈公开页** (chanmama.com) | 部分公开数据：达人粉丝、商品排行片段 | web_extract | 详细数据需付费，页面可能 JS 渲染 |
| **飞瓜数据公开页** (feigua.cn) | 类似蝉妈妈 | web_extract | 同上 |
| **抖查查公开页** (douchacha.com) | 部分达人/商品数据 | web_extract | 同上 |
| **百度指数** | 品类搜索热度趋势 | web_search | 间接信号 |
| **微信指数** | 品类/品牌微信热度 | 微信搜一搜 | 需手动操作 |

### 三级渠道（低置信度，仅作参考）

- 行业自媒体发文（数据准确性存疑）
- 品牌方公开战报（可能夸大）
- 社群截图转述（无法验证）

## 六大分析模块（数据采集 + 成功概率判断）

### 模块一：爆款选品（Product Discovery）

**目标**：找到某个品类近期增长快的商品，评估入场价值。

**数据获取方法**：

```yaml
搜索策略（并行发出）:
  - search: "{品类} 抖音 热卖榜 2026 月销"
  - search: "{品类} 抖音 爆品 销售额"
  - search: "site:ebrun.com 抖音 {品类} 热卖"
  - search: "site:ctoy.com.cn 抖音 玩具 月销"  # 如果是玩具品类
  - search: "{品类} 1688 热销 代发 抖音同款"
```

**输出模板**：

| 维度 | 内容 |
|------|------|
| 商品名 | 来源渠道备注 |
| 售价区间 | 精选联盟/1688 |
| 月销估算 | 按渠道标注置信度 |
| 竞争程度 | 同款估算卖家数（多/中/少） |
| 适配理由 | 一行，直接说为什么适合你 |
| 风险点 | 材质/尺寸/合规/生命周期 |

**执行 Checklist**：
- [ ] 用 web_search 并行搜4个方向
- [ ] 有明确榜单的用 web_extract 提取数据
- [ ] 按销量门槛过滤（严格按用户要求）
- [ ] 交叉验证至少2个来源
- [ ] 标注每个数据的置信等级

### 模块二：竞品店铺侦察（Competitor Shop Recon）

**目标**：分析某个抖音店铺的销售策略、GMV结构、合作达人。

**获取方法**：

```yaml
搜索策略:
  - search: "{店铺名/品牌名} 抖音 店铺 销售额"
  - search: "{店铺名} 抖音 达人 合作"
  - search: "{店铺名} 蝉妈妈 数据"  # 有时会有公开页面
  - search: "site:douyin.com {店铺名}"  # 找到店铺主页
  - search: "{店铺名} 抖音 直播 GMV"
```

当有店铺主页或第三方平台页面时，用 web_extract 尝试提取。

**输出模板**：

```markdown
## 竞品侦察：{店铺名}

| 维度 | 数据 | 置信度 | 来源 |
|------|------|:-----:|------|
| 90天估算GMV | XXX万 | 中/低 | 第三方推算/公开战报 |
| 主要类目 | XX | 高 | 公开信息 |
| 合作达人量级 | XX个 | 中 | 公开页面/推算 |
| 主力价格带 | XX-XX元 | 高 | 精选联盟可查 |
| 销售结构 | 视频: XX% / 直播: XX% / 广告: XX% | 低(估算) | 行业经验推算 |

**可观测打法的要点**（从公开素材推断）：
- 直播频次：每天X场 / 每次X小时
- 短视频数量：日更X条 / 内容风格
- 达人合作模式：纯佣/坑位费/混佣
- 主力引流品：XXX（售价最低/带流量）

**反制建议**（模仿FastMoss风格）：
> 核心建议一句说清楚，如"用 XX 价格带错位竞争，挖他们腰部达人"
```

**输出模板**：

| 维度 | 内容 |

### 模块三B：精选联盟达人筛选协作（用户有后台权限时）

**核心认知**：Agent **不能直接访问** `buyin.jinritemai.com`（需用户扫码登录 + 2FA 验证，自动化登录有安全风险会触发封号；Camofox 浏览器已配置但仅用于公开数据页）。必须依赖用户导出数据或截图，Agent 负责分析。

**适用场景**：用户在精选联盟达人广场筛选后，把数据（粘贴/截图）发给你分析。

**用户典型筛选链**（来自实际会话）：
1. 按结算总额从高到低排序
2. 手动看达人带的品是否匹配
3. 剔除付费渠道占比高的达人（精选联盟后台有该字段，Agent 无法访问）
4. 优先 V0-V1 等级
5. 粉丝量 10 万以内，月销售额 10 万-500 万区间
6. 客单价在 19.9-399 之间

**用户数据提交方式**：
- 全页复制粘贴 → 但分页加载会导致数据不全，建议补截屏
- 截屏 → 最简单的方案，每屏截图即可
- 长截图 → Chrome 开发者工具 `Command+Shift+P` → `Capture full size screenshot`

**数据接收后，Agent 分析要点**：

| 分析维度 | 怎么做 | 价值 |
|---------|-------|------|
| **销售渠道结构分析** | 对比直播结算 vs 视频结算 vs 图文结算 vs 橱窗结算的占比，判断达人类型 | 直播型达人需直播合作才有效；内容型达人才适合纯佣挂车 |
| **佣金率 vs 销量 ROI 测算** | 用公开客单价估算"每给 1 块钱佣金换多少 GMV" | 判断合作性价比 |
| **低粉高转化挖掘** | 找出粉丝少但结算总额高的达人 | 后台按粉丝排序会漏掉 |
| **最优佣金组合建议** | 根据销量分布反推该设几档佣金 | 优化合作策略 |

**实战关键发现**（2026年7月实际数据验证）：
- 精选联盟达人广场**大部分达人直播结算占 90%+**，视频/图文带货极弱
- 这意味着：如果不做直播投放/坑位费合作，纯靠挂车佣金，大多数达人不强推你的品
- 只有「视频结算 + 图文结算」占比 > 20% 的达人，才适合"寄样→挂车→出视频"的纯佣模式
- 单看月销高不看渠道结构，容易选错合作方式

**注意事项**：
- 用户提供的达人数据中，「综合匹配度」「回复率」「潜力合作」等标签是后台字段，Agent 不能校验真伪
- 付费渠道占比数据 Agent 拿不到，依赖用户自己在后台人工剔除
- 若用户卡在"怎么导出数据"，直接给 Chrome 长截图方案，不要建议复杂操作

**参考文件**：`references/creator-selection-xuanlian.md`

### 模块六：商品成功率判断（5层信号塔）⭐⭐

> 综合前5个模块采集的数据，对一个候选品输出成功概率区间、开发/暂缓/砍掉决策、首单量建议、售价建议。

**适用场景**：用户问"这个品能不能做"、"成功率多高"、"该不该上"、"帮我筛一批品"。

**5层信号权重**：

| 信号层 | 权重 | 核心问题 | 关键数据源 |
|-------|------|---------|-----------|
| 需求信号 | 30% | 有人在搜这个品吗？ | 亿邦月榜、百度指数、抖音搜索量 |
| 竞争信号 | 25% | 能挤进去吗？ | 同款卖家数、头部集中度、达人活跃度 |
| 利润信号 | 20% | 能赚钱吗？ | 毛利率、佣金后净利、退货率 |
| 平台适配 | 15% | 平台会推它吗？ | 内容化潜力、价格带匹配、佣金结构 |
| 供应链 | 10% | 能稳定做吗？ | 供应商替代数、MOQ、交货周期 |

**综合判定（55分制）**：

| 总分 | 评级 | 动作 |
|-----|------|------|
| ≥40 | 高成功概率 | 开发 + 首单量建议 |
| 30-39 | 中成功概率 | 暂缓观察，补全缺失数据 |
| 20-29 | 低成功概率 | 跳过 |
| <20 | 不建议入场 | 直接砍 |

**平台差异化**：同一个品在抖音/淘宝/拼多多得分不同。确定目标平台后再调用此模块。

**输出模板**：

```markdown
## 成功率判断：{商品名}
| 信号层 | 得分 | 关键数据 |
|--------|:----:|---------|
| 需求(/20) | 17 | 搜索增速35%↑ 月销8000单 |
| 竞争(/15) | 12 | 同款30家 头部集中度中 |
| 利润(/15) | 14 | 毛利率55% 退货率4% |
| 平台适配(/5) | 4 | 易展示 佣金25%+ |
| **总分(/55)** | **47** | **✅ 高成功概率 → 开发** |
```

## 数据置信度标注规范

所有输出的数据必须带置信度标签：

| 标签 | 含义 | 典型来源 |
|:----:|------|---------|
| 🔵 **高** | 官方发布/第一手公开数据 | 抖音官方榜、亿邦月度榜 |
| 🟡 **中** | 第三方推算/合理估算 | 各平台免费页面片段 |
| 🔴 **低** | 行业推测/定性描述 | 自媒体文章、社群消息 |
| ⚪ **无数据** | 没有找到可靠来源 | 编造？不存在 |

**绝对禁止**：
- ❌ 把"无数据"写成"高"或默认不加标签
- ❌ 把单个来源的推测数据写得太精确（如说"月销37,482件"）
- ❌ 用一个低信度来源不加警告就下结论

## 五步执行法（标准工作流）

### Step 1：需求明确
- 用户要什么？选品/竞品/达人/类目/店铺诊断？
- 具体品类/品名/店铺名/达人是谁？

### Step 2：多源数据采集
- 根据模块选择，并行发出3-5个搜索
- 对有结果的页面做 web_extract
- 记录每个数据的来源和置信度

### Step 3：结构化分析
- 按对应模板输出分析报告
- 用表格，不要长篇叙述
- 每个品/店/达人一行

### Step 4：成功率判断
- 如果用户要选品决策，调用模块六计算成功概率
- 综合前5个模块数据，输出高/中/低成功概率 + 首单量建议
- 标注平台差异（同品在抖音/淘宝/拼多多得分不同）

### Step 5：建议 + 风险标注
- 给直接的建议（优先XXX，因为XX）
- 附风险标注（竞争/退货/合规/供应链）
- 附带成功率区间

### Step 6：下一个动作
- 给一个用户马上能做的动作
- 如果判断为高成功概率，给首单量和生产节奏建议

## 降级策略：当 web_search/web_extract 不可用时

`web_search` 和 `web_extract` 依赖第三方 API（Firecrawl），当 API 额度耗尽时返回 `Payment Required` 错误。此时必须使用 `computer_use` 进行浏览器直连搜索。

### 降级切换判断

```
if web_extract 返回 "Payment Required" 或 HTTP 402/403:
  1. 停止使用 web_search/web_extract
  2. 改用 computer_use + Safari 浏览器直接搜索
  3. 用户系统上的 Safari/Chrome 可正常访问网站
```

### macOS Safari 使用注意事项

| 问题 | 解决方法 |
|------|---------|
| Safari 有后台进程但无窗口 | `open -a Safari "https://..."` 打开新窗口 |
| Windows 在后台但 capture 不到 | `computer_use(action='focus_app', app='Safari')` 有时报错但仍可用 |
| Baidu/Google 搜索结果中的链接 | 找到元素 index 后用 `computer_use(action='click', element=N)` 点开 |
| 页面是 Nuxt/SPA 渲染 | `computer_use(mode='som')` 可以捕获 AX 渲染后的内容，curl/web_extract 拿不到 |
| 站点有 WAF/CAPTCHA | 提示用户手动验证（中外玩具网 ctoy.com.cn 有堡垒云滑块验证） |

## 进阶：用 computer_use 获取登录后数据

当免费渠道拿不到足够数据时，如果用户已登录以下平台，可配合 computer_use 直接提取。

**标准操作流程**：

```yaml
1. 打开 Safari 并导航到目标网站:
   open -a Safari "https://目标平台.com/目标页面"
   （等待约 3-5 秒让页面加载）
   
2. 用 som 模式捕获页面:
   computer_use(action='capture', mode='som')
   （返回所有交互元素的 AX 树 + 编号截图）
   
3. 提取搜索结果的链接:
   从返回的 elements[] 中找到 AXLink 元素，
   筛选标签长度 > 8 且不含导航关键词的链接
   
4. 点击目标链接:
   computer_use(action='click', element=N)
   
5. 再次 capture 获取目标页面内容
```

## 已知限制

| 限制 | 说明 | 应对 |
|------|------|------|
| 抖音强反爬 | 站内页面JS渲染，web_extract拿不到结构化数据 | 降级到第三方/公开渠道 + computer_use浏览器直连 |
| 第三方平台付费墙 | 蝉妈妈/飞瓜等核心数据需付费 | 用免费公开页面 + 多源交叉验证 |
| web_search/web_extract API额度耗尽 | Firecrawl返回"Payment Required" | 切换到 computer_use + Safari 浏览器直接搜索 |
| 无 API | 国内没有像 FastMoss 这样的公开 MCP 服务 | 依赖搜索+提取+浏览器直连的间接方式 |
| 时效性 | 公开榜单可能滞后1-2周 | 标注数据时间；快消品类更明显 |
| 无法精确销量 | 月销数据大多数平台不公开 | 用区间估值（千/万/十万级），不伪造精确数字 |
| 精选联盟后台不可访问 | buyin.jinritemai.com 需用户扫码登录 + Camofox浏览器未运行 | 用户导出/截图数据，Agent 负责分析（见模块三B） |
| macOS Safari 窗口不可见 | list_apps 显示 Safari 但 capture 不到 | 先 `open -a Safari "URL"` 确保窗口存在 |
| WAF/CAPTCHA拦截 | 中外玩具网等使用堡垒云/其他WAF | 提示用户手动完成验证后继续 |

## 常见误区

- ❌ 把1688的"热销指数"当成抖音销量 → 1688是B2B批发数据，只能做供应链参考
- ❌ 用知乎/小红书的"种草热度"替代销量数据 → 声量≠销量，尤其高客单品
- ❌ 说"这个品月销10万+"但没有来源 → 必须标注来源和置信度
- ❌ 所有的搜索都是搜个大概然后开始编 → **数据驱动，先搜再写**
- ❌ 把成功率写成精确值 → 输出必须是区间（高/中/低），不要写"成功率68%"
- ❌ 忽略平台差异用同一套权重打分 → 抖音重内容化，淘宝重评价权重，拼多多重低价，权重必须不同
- ❌ 认为一次打分就准了 → 新品类没有历史数据误差大，必须积累回测数据迭代权重
