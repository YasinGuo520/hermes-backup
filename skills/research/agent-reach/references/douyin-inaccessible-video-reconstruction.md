# 抖音/B站短视频内容重建工作流（无法直接访问时）

当用户分享的抖音（或B站/小红书）视频链接因反爬/登录墙/地域限制无法直接访问时，通过**多源三角验证**重建视频核心内容，避免"我打不开"的僵局。

## 触发场景

- 用户发抖音视频链接 → web_extract 返回空/错误
- 用户发 B 站视频 → web_extract 只抓到页面壳（无内容/无字幕）
- 用户发小红书链接 → 页面要求登录

## 三角验证工作流

### 第一步：解析搜索关键词

从用户消息中提取关键词组合：

```
[创作者名称] + [视频标题关键词] + [话题标签]
```

例：用户发 "光羽 # 企业AI变革 # 程泓宁"
→ 关键词：`程泓宁 光羽 宇宙ebike AI 20人`

### 第二步：多通道交叉搜索

同时并发搜索以下来源：

| 搜索源 | 搜索策略 | 目标 |
|--------|---------|------|
| web_search | 视频标题/话题标签全文匹配 | 找到文章/播客/新闻引用该视频内容 |
| web_search | 创作者名 + 核心主题 | 找到创作者的其他访谈/文章中谈及的同类观点 |
| web_search | 创作者空间页面（如 bilibili 用户主页） | 获取视频简介、播放量、发布时间 |
| web_search (site:douyin.com) | 视频ID或关键词定向搜索 | 有时能抓到评论/简介片段 |

### 第三步：上下文重建（无文字稿时的核心技巧）

当抓不到视频文字稿时，**不要只给笼统分析**。用以下方法重建：

1. **创作者画像推断**
   - 搜该创作者的其他访谈/播客/长文（如程泓宁有「三五环」播客深度访谈）
   - 提取其核心观点、做事风格、方法论体系
   - 这些长文内容通常覆盖短视频中的核心论点

2. **业务模型反推**
   - 分析创作者的公司/产品业务模型（如：宇宙ebike = 制造业+电商+内容+私域）
   - 推演在这样的业务模型中，AI agent 的可能应用场景
   - 用行业共识 + 特定公司现状交叉验证

3. **行业知识映射**
   - 引用公开的行业趋势数据/方法论（如百融云创、微盟WAI的Agent案例）
   - 说明这些是"行业普遍做法"而非视频原话
   - 明确标记哪些是推测（"基于业务推断"），哪些是公开信息

### 第四步：输出格式规范

输出应包含：
1. **背景脉络**——创作者是谁，公司做什么，什么规模
2. **岗位-应用映射表**——（建议表格：岗位 | Agent应用方式 | 具体怎么做）
3. **核心逻辑总结**——（不是"他说了什么"，而是"这个模式为什么work"）
4. **对你可落地的最大化借鉴**——（直接可执行的行动项，分"今天可做/3天可做/本周可做"）

### 第五步：风险提示

在输出顶部或底部加一句免责说明：

> ⚠️ 视频文字稿未直接获取，以下分析基于**[公开访谈/行业数据/业务模型推断]**综合重建，部分细节可能与视频原话有出入。

## 注意事项

- **不要假装看过视频**——坦诚告知无法直接访问，但用重建方式弥补
- **优先搜索已有文字稿的来源**（播客转写/公众号文章/新闻稿）比纯推断更可靠
- **区分"视频明确提到的"和"我推断的"**——在分析中做明确标记
- **当什么信息都找不到时**：基于创作者身份+公司业务+行业通用做法给出合理推断，但必须注明推断性质
- **永远不要给空洞的"等视频出来后再分析"**——用户就是等你干活，不是等你推活

## 🚨 铁律：不要修工具，直接问用户（实战教训）

当你尝试访问视频链接但失败时，最短路径法则：

**错误的做法（本 session 的翻车路径）：**
1. ❌ 浏览器弹验证码 → 修浏览器（debug GFW 问题、下载 addon、重启服务）
2. ❌ 浏览器仍不行 → 换工具（Playwright、SSH 到远程服务器）
3. ❌ 工具仍不行 → 搜近似关键词 → 把"5个skills"当作"10个skills"的答案 → 用户怒了

**正确的做法（0 秒切换到最短路径）：**
1. ✅ `web_extract` → 失败
2. ✅ `browser_navigate` → 验证码/反爬/空页面
3. ✅ 直接说：**"这个链接我打不开。你那N个分别是什么？"**

**原理**：修工具 30 分钟 vs 问用户 10 秒。用户最烦的是你绕了一大圈给个错误答案。用户自己知道答案。

## ⚠️ 关键陷阱：Douyin 分享链接编码格式

抖音的分享文本格式如 `1.23 :1pm JiP:/ 04/15 s@r.re 标题...` 是**编码后的短链**，无法从中提取视频 ID 直接访问。

**错误的做法：**
1. ❌ 用这个文本里的任何片段去 web_search，把搜到的第一个近似视频当作原视频
2. ❌ 看到一个描述说"5个skills"就贸然下结论——可能是另一个视频
3. ❌ 用户说"有10个"还坚持自己的5个结果

**正确的做法：**
1. ✅ 诚实告知"这个链接编码我解析不了视频ID，打不开原视频"
2. ✅ 同时用视频标题关键词 + 创作者名 + 所有话题标签组合搜索
3. ✅ 搜索后不要急着给结论——如果搜到的结果与用户描述矛盾（如用户说有10个skill但你搜到5个），先停顿：
   - 检查有没有同一个主题但不同skill数量的其他视频
   - 通过B站/TikTok/小红书等备选平台交叉搜索同名内容
   - 检查用户话题标签是否有专指某条视频的独特组合
4. ✅ 如果仍然不确定，直接问用户：**"我打不开这个视频，你能告诉我那N个skill分别是什么吗？"** — 给错误答案比说不知道更糟糕
5. ✅ 最终输出必须加 ⚠️ 免责标注：若未100%确认是原视频，必须说明信息来源的局限性

## 不适用场景

- 视频内容涉及具体数据（销量、佣金、转化率）——不要编造，直接用"未获取到具体数据"
- 视频是纯娱乐/展示类内容无干货——诚实告知，不硬塞分析
- 创作者无明显公开信息——找替代内容或让用户提供更多上下文
