# 中国市场行业调研 (China Industry Research)

> **网页版已上线**：http://43.138.221.174:8923/（输入需求/候选方向 → DeepSeek 按本方法论出赛道全景对比 + 五维评分⭐ + 年入千万路径 + TOP3）。工具箱 8900 有入口。搭建模式见 `ai-analysis-landing-pages` skill。

## 适用场景

需要快速了解中国某个垂直行业的市场规模、竞争格局、创业机会时使用。特别适合：
- SaaS/小程序/APP方向的市场调研
- 中国消费市场细分赛道分析
- 竞品格局与技术壁垒研究
- 为创业者提供赛道推荐与风险评估

## 调研方法论

### 并行调研（推荐策略）

对于多方向、跨赛道的调研（如同时调研男性/女性/老年/本地生活四大赛道），使用 `delegate_task` 并行派遣子Agent：

1. 父Agent定义调研范围和输出格式模板
2. 为每个方向派遣一个子Agent（`delegate_task`，最多3个并行）
3. 每个子Agent独立执行下面的方法论（搜索→采集→输出）
4. 父Agent等待所有子Agent完成后，执行「全景整合」步骤

**全景整合步骤**（父Agent执行）：
1. 收集所有子Agent的返回摘要
2. 横向对比各赛道的市场规模、竞争度、AI契合度
3. 按「人欲」分类（男性赚钱好色、女性爱美育儿、老年养生陪伴等）重组
4. 计算各赛道的年入千万路径（客单价×所需客户数）
5. 输出最终「终极TOP5推荐」压缩为一页可对比的表格
6. 可选：将完整报告写入Obsidian并关联索引

### 搜索降级链路

### 第1层：搜索引擎（优先顺序）

```
DuckDuckGo (https://lite.duckduckgo.com/lite/?q=关键词) ← 最可靠，纯文本
  → SearXNG / Brave Search (fallback)
  → Baidu (受限时跳过，不阻塞)
  → Google (可能超时，但值得尝试)
```

**注意 1**: 从海外/中国服务器环境访问中文网站时，Baidu/36氪/虎嗅/知乎等经常触发反爬或验证码。这是正常现象——**不要阻塞在这个环节**，降级到下一层。

**注意 2**: Bing 国际版 (`www.bing.com/?cc=US&setlang=en-US`) **从中国IP始终被重定向到 cn.bing.com**，且无论点「国际版」还是设置参数都无法绕过。不要在此浪费轮次。cn.bing.com 的浏览器AX树也不呈现搜索结果链接——HTML虽包含结果但无障碍树截断了。

**注意 3**: DuckDuckGo 的 HTML 版 (`lite.duckduckgo.com/lite/`) 纯文本返回，是 Web Search 中最可靠的方案。但有时也返回空结果（DNS/连通性问题）。

### 第2层：Python搜索库（当浏览器搜索返回无关结果时）

```python
# 推荐使用 ddgs 库（注意：老版 duckduckgo_search 已重命名为 ddgs）
pip install ddgs requests beautifulsoup4 lxml

from ddgs import DDGS
with DDGS() as ddgs:
    for r in ddgs.text("查询关键词", max_results=10):
        print(r.get('title'), r.get('href'))
```

### 第4层：36氪/知乎直接URL访问（绕过SPA搜索限制）

36氪和知乎的搜索页是SPA（JavaScript渲染），curl获取不到结果。但它们的**单篇文章**URL是服务端渲染的，可以直接访问：

```
# 36氪单篇文章示例
https://36kr.com/p/1234567890123456   ← 直接访问可获取全文

# 36氪搜索页（SPA，curl不可用，但浏览器可以加载）
https://www.36kr.com/search/articles/关键词
```

**策略**: 先通过Bing/百度等搜索引擎找到36氪/知乎的具体文章标题或ID，再直接访问单篇文章URL。不要尝试从36氪搜索页抓取结果列表。

### 第5层：产品官网/行业网站直接访问

当通用搜索引擎不可靠时，直接访问已知的行业产品官网或垂直媒体：

| 目标 | URL | 内容类型 |
|------|-----|---------|

这些站点通常服务端渲染，curl可以直接获取有价值的产品信息和行业描述。

### 第6层：知识综合（当搜索数据不足时的兜底策略）

当搜索只能获取碎片化数据、或所有搜索引擎均不可用时，按以下框架从训练知识中综合输出：

1. **盘点已有知识**：对该方向的现有产品、公司、市场规模、用户量级做一次脑内扫描
2. **市场基线数据**：引用已知的可靠数据（如2024年中国60岁以上人口2.97亿，银发经济7.5万亿），标注"估算"或"基于已知数据"
3. **竞品格局绘制**：从碎片信息中提取已知玩家，形成竞品对比表（名称、规模、商业模式、融资情况）
4. **赛道拆分**：将大方向拆分为3-6个细分赛道，逐一评估市场规模、竞争度、AI契合度
5. **创业者路径推荐**：基于市场空白+AI技术能力+冷启动难度，给出优先级排名
6. **数据标注**：所有非一手来源的数据标注"估算"或"仅供参考"
7. **输出到文件**：将报告保存为 `.md` 文件，路径 `{工作目录}/{方向}创业机会调研报告.md`

**本次会话验证的工作流**：当 Web Search 全面失效时（百度 captcha、Bing 国内版无搜索结果、Google 超时、DuckDuckGo 空返回、36kr SPA 无内容、知乎动态加载），最终输出是一份完整的行业调研报告，完全基于训练知识 + 结构化模板输出。核心原则：**不因搜索受限而拒绝输出，降级到知识综合并明确标注数据性质即可**。

### 评分标准
- 市场规模: ⭐1-5（百亿以下1星，万亿级5星）
- 竞争度: ⭐1-5（竞争少=高星，红海=低星）
- AI契合度: ⭐1-5（AI能否建立核心壁垒）
- 冷启动难度: ⭐1-5（容易启动=高星）
- 年入千万难度: ⭐1-5（容易达成=高星）

## 常见陷阱

1. ❌ **卡在某个搜索工具上浪费时间**。如果一轮搜索（Bing/DuckDuckGo/百度）返回无关或空结果，立即降级到下一层。不要同一引擎重试3次以上。
2. ❌ 把无法访问的站点当作"结论"（如"Baidu搜索无结果"不等于市场不存在）。
3. ❌ **依赖浏览器AX树获取Bing搜索结果**。cn.bing.com 的搜索结果是服务器端渲染的，但浏览器AX树（无障碍树）不呈现这些结果链接，仅显示搜索框和导航。Bing 的 HTML 中确实有 `<h2><a href=...>` 格式的结果链接，但 AX 树截断了它们。如果你必须用 Bing，用 curl 直接抓取 HTML 并用正则解析。
4. ❌ **从中国IP访问 Bing.com 始终被重定向到 cn.bing.com**，无论设置 `cc=US&setlang=en-US` 还是用 `www.bing.com` 域名都无法绕过。直接放弃 Bing 国际版路径。
5. ❌ **用 curl 抓取 SPA 站点（36kr/知乎）期望获取正文**。这些是 JavaScript 渲染的单页应用，curl 获取的 HTML 仅含框架和打包 JS，不含文章正文。必须通过浏览器（如果可以）或直接降级到第4层。
6. ❌ **搜索关键词太长**。中文搜索引擎对超过6个词的查询匹配很差，优先用2-4个词的短查询。
7. ✅ 多个搜索引擎返回的数据交叉验证。
8. ✅ 明确区分"直接引用数据"和"基于经验/训练知识的估算"。
9. ✅ 报告末尾标注详尽的数据来源和免责声明。
10. ✅ **搜索全面失败时立刻切到第4层知识综合**，不要反复重试同一工具。
11. ✅ **并行调研有限制**：`delegate_task` 最大并行数由 `delegation.max_concurrent_children` 配置决定（默认3），超出会同步执行。不需要改配置，同步执行只是慢一点，不影响结果。
12. ✅ **多子Agent返回后需要全景整合**：子Agent返回独立方向的详细报告，父Agent负责横向对比、合并、生成紧凑版全景表。这是关键步骤，不要直接抛子Agent的报告原文给用户。
13. ✅ **子Agent不记得会话上下文**：派遣时在`context`字段包含全部必要信息（用户背景、偏好语言、输出格式要求），否则子Agent可能用英文回复或遗漏关键约束。
14. ✅ **子Agent结果不完全是事实**：子Agent返回时可能声称\"报告已写入文件\"但实际上写入的是别的路径。收到子Agent完成通知后，用`read_file`验证文件存在且内容正确再引用。
15. ✅ **年入千万路径计算**：不要只看市场规模，要给出具体的"客单价×客户数"路径。公式：年入千万 = 月入83万 ÷ ARPU。不同客单价对应的客户数差异极大（¥99/月需841家，¥10万/年只需10家）。
