### 市场调研方法论（PM面向产品决策，区别于通用市场调研）

PM的市场调研焦点是**"痛点量化 + 竞品定位 + 用户角色画像"**，不是泛泛的行业数据。推荐以下搜索模式：

#### 1. 痛点数据获取 → 优先学术论文/公开调查报告

```python
# 用 batch_search 并行查3类来源
batch_search(queries=[
  {"query":"[目标人群] 痛点 调查 统计 报告"},        # 定量数据
  {"query":"[目标人群] 每天 工作时间 耗时"},           # 时间成本/效率缺口
  {"query":"[目标人群] 调研 报告 2024 2025"},          # 最新行业报告
])
```

提取核心数据点的方式：从搜索结果的摘要或全文提取含数字的句子（百分比、小时数、人数等），并用星号标注来源论文/报告名称。

#### 2. 竞品分析 → 直接访问官网 + App Store

每个竞品必须获取以下维度，用统一表格呈现：

| 竞品 | 所属公司 | 产品类型 | 核心功能 | 商业模式 | 宣称用户量 | AI能力 | **与我们的差异（一句话）** |
|------|---------|---------|----------|---------|-----------|--------|------------------------|

**数据来源**: 官网宣称数字、App Store评分/评论数（评论数×30-50≈下载量估算）、行业报告引用。禁用推测性数据。

**竞品定位矩阵**: 将竞品放到二维坐标中（维度根据赛道选，例如：轻量↔重量 / 纯工具↔AI原生↔游戏化），标出目标空白位。

#### 3. 行业趋势 → 巨头布局 + 政策文件 + 财务数据

```python
batch_search(queries=[
  {"query":"AI [行业] 工具 赛道 2025 2026 发展"},
  {"query":"[行业] 市场规模 2025 2026 预测"},
  {"query":"生成式AI [行业] 应用 合规 监管"},
])
```

产出形态：对每个趋势点给出"趋势 → 影响 → 应对策略"三联结构。

### 双端产品检查（✅ 必须完成）

> 如果产品有**两群用户**（A买单、B使用），必须检查**B端用户的参与动力**。

#### 常见双端结构

| 类型 | 买单方 | 使用方 | 检查重点 |
|-----|-------|-------|---------|
| 教育工具 | 老师/家长 | 学生 | **学生为什么愿意用？** 纯工具缺乏趣味性→需要游戏化/奖励机制 |
| B2B2C | 企业 | 终端用户 | 终端用户有没有替代方案？用你的有什么好处？ |
| 内容平台 | 创作者 | 消费者 | 消费者为什么愿意来？内容供给够了没？ |

#### 检查清单

| 问题 | 不合格标志 |
|-----|-----------|
| B端（使用方）用户有内在动力使用吗？ | 需要靠A端强制，B端自己不想用 |
| B端用户的参与是否对A端消费者有价值？ | B端参与不参与A端都无所谓 |
| 产品对B端用户的吸引力跟竞品（如游戏/宠物）对比如何？ | 竞品更好玩，用户选了竞品 |
| 如果B端用户不玩了，A端还会继续付费吗？ | 不会 → 产品必死 |

#### 案例

```
❌ 失败案例（AI班级管家纯工具版）：
  A（老师）= 省时间 ✅ 愿意付费
  B（学生）= 跟我没关系，不如去玩蛋仔派对 ❌ 
  → 老师发现学生不care → 老师不推荐 → 传播断裂 ❌

✅ 修正版（AI班级管家 + Agent宠物）：
  A（老师）= 省时间 ✅ 愿意付费
  B（学生）= 养AI Agent，能进化能聊天，比纯积分好玩 ✅
  → 学生主动参与 → 老师看到效果 → 老师更愿意推荐 ✅
```

### 边际成本致命性检查（✅ 必须完成）

> 这是所有项目的**必答题**，不通过则项目直接淘汰。

#### 检查项

| 问题 | 计算公式 | 合格标准 |
|-----|---------|---------|
| 每用户每月成本 | 日均调用次数 × 单价 × 30 | **必须 < 每用户每月收入** |
| 长期使用亏损 | 每用户每月成本 × 6/12个月 | 必须 < 买断单价（如果是买断制） |
| 规模放大效应 | 100/1000/10000用户时的总成本 | 成本增速必须 < 收入增速 |
| API费用拐点 | 什么DAU时API费超过收入？ | 拐点越高越好 |
| **买断制检查** | 用户用满12个月时，我的总成本 > 我收的钱？ | **买断制下必须为NO，否则改为订阅制** |

#### 案例（修正版）

```
✅ 买断制可行案例（班级管家¥19.9买断制）：
  用户日均调用14次，月消耗~60,000 tokens（含缓存命中）
  以DeepSeek V4 Flash计价（用户1亿token≈¥5）：
  月API成本 ≈ ¥0.003（中度用户）
  年API成本 ≈ ¥0.036
  买断收入 = ¥19.9
  结果：买断制完全可行，用户用3年也大赚 ✅

❌ 致命错误案例（按次估算，不按token）：
  用"每次调用¥0.01-0.02"估算 → 成本高估1000倍
  正确：①问用户实际API单价 ②按日均调用×每次tokens算月消耗
```

**⚠️ API成本估算原则（硬性规定，所有分身遵守）：**
- **不能按「每次调用x元」算，必须按token消耗算**
- 不同模型/缓存命中率/峰谷时段价格差距极大（差50倍以上）
- **必须问用户实际价格，官网价不可用。** 问法：\"你1亿token实际要多少钱？\" 用户回答就是基准值
- 单次调用token数参考：简单记录~90 tokens / 生成通知~500 tokens / 复杂推理~1000+ tokens
- 计入峰谷差异：老师/办公类产品大部分在工作时段（高峰），按70%高峰+30%低谷加权
- **交叉验证规则：** 成本算出后必须让产品经理和财务总监分别独立计算。两组结果差>20% → 重算

### 财务预算模型（产品侧）

#### 三层次定价设计原则

1. **基础免费层** — 获取用户（限制功能/次数，制造付费动机）
2. **买断/订阅核心层** — 主要收入（覆盖80%功能需求）
3. **增值服务层** — 延展收入（产品成熟后再上，自然延伸）

#### 收入估算核心公式

```
买断收入 = 注册用户 × 试用→付费转化率 × 单价
IAA收入  = DAU × 日均广告次数 × 30天 × eCPM/1000 × 分成比例  
增值收入 = 付费用户 × 增值品付费率 × 增值品均价
```

#### 盈亏平衡点计算

| 项 | 公式 |
|----|------|
| 保本用户数 | (固定开发成本 + N月运营成本) / 单用户平均收入 |
| 月保本买断人数 | 月运营成本 / 买断单价 |
| 预期月买断转化率 | 参考同类产品（工具类5-10%，教育类略低3-8%） |
| 预期日新增注册 | 按渠道和推广力度估算 |

#### 三情景预测原则

| 情景 | DAU增长 | eCPM假设 | 增值/变现假设 |
|------|---------|---------|-------------|
| 悲观 | 缓慢线性增长 | 下限 | 无/难 |
| 中性 | 线性增长 | 中位 | 部分落地 |
| 乐观 | 加速增长 | 上限 | 顺利 |

### 详细模块编制指南

#### 收入模型编制方法

IAA收入核心公式：
```
IAA月收入 = DAU × 日均激励视频次数 × 30天 × eCPM / 1000
              + DAU × 日均插屏频次 × 30天 × 插屏eCPM / 1000
```

**行业基准参数（2024-2025微信小游戏实测数据）：**
- eCPM 激励视频：¥18-45（塔防品类中位≈¥28，需每周追踪）
- eCPM 插屏广告：¥12-25（约为激励视频60-70%）
- 人均激励视频/日：2.5-6次（中度休闲品类均值3-5次）
- 插屏频次控制：约每3关1次（避免影响留存）
- 广告填充率：正常>85%，低于60%为警戒线
- 微信广告分成比例：IAA开发者得50%（流水分成后）

IAP收入核心公式：
```
IAP月收入 = DAU × 付费率 × ARPPU
```
- 付费率基准：休闲1-3%，中度2-5%，重度3-8%
- ARPPU基准：¥6-25（微信小游戏中位¥8-15）

B端收入：按客户数 × 年均客单价 / 12 逐月均摊
- 教育SaaS客单价：¥3-15万/年
- 销售周期：3-6个月

订阅收入：DAU × 订阅转化率 × 月订阅价格
- 转化率基准：0.3-2%

**三情景设置原则：**
- 乐观 = DAU加速增长 + eCPM偏上限 + IAP/B端顺利
- 中性 = DAU线性增长 + eCPM中位 + IAP/B端部分落地
- 悲观 = DAU缓慢增长 + eCPM偏下限 + IAP/B端难以启动

#### 成本结构编制方法

**固定成本（月度）：**
- 人力：全职工资 + 兼职外包
- 基础设施：云服务器/CDN/数据库/域名
- 第三方SDK：统计/广告SDK费用
- 工具订阅：设计工具/项目管理/源代码管理

**可变成本：**
- 买量CAC（用户获取成本）：微信CPA广告 ¥1-5/注册
- AI API调用费：按次计费（70%可缓存降低）
- 支付通道费：IAP收入 × 30%（微信+苹果税）
- 内容更新外包：新关卡/术语/美术素材制作
- 客服外包：每万DAU约¥1,000
- B端销售佣金：客单价的10-20%

**边际成本分析：** 按DAU区间分段计算
- 关键是找到"边际成本增速 < 边际收入增速"的拐点
- 互联网产品典型规律：DAU每翻倍，边际成本增长40-60%，边际收入增长~100%

#### 融资需求分析框架

1. **峰值资金需求**：三个情景分别计算最大累计亏损 + 出现月份
2. **最低资本要求**：峰值资金需求 × 1.2（安全系数）
3. **建议融资额**：建议储备 = 最低资本要求 + ¥10-20万安全垫
4. **融资方案对比**：多种金额 × 对应出让股份方案
5. **融资ROI**：资金带来的买量加速 / 时间节省 vs 股权稀释成本

#### 估值分析三法

**1. 对标法（Comparable Company Analysis）：**
- 微信小游戏公司：P/S 3-5×
- 教育游戏/科技公司：P/E 15-25×（教育溢价）
- 小游戏并购案例：P/DAU ¥20-80
- 教育SaaS预案：5-8× ARR

**2. 现金流折现法（DCF）：**
- 折现率：初创游戏公司30-40%（高风险溢价）
- 预测期：3年
- 终值增长率：3%
- 终值 = 第3年FCF × (1+g) / (r-g)
- 注意：早期项目DCF估值对折现率极度敏感

**3. 用户价值法：**
- 月ARPU = 月总收入 / DAU
- LTV = 月ARPU × 留存调整后的生命周期（通常12-24个月）
- 用户价值法估值 = LTV × 当前DAU（保守法）
- LTV/CAC > 3.0 是健康指标

#### 退出路径分析方法

按概率/回报矩阵分析：

| 退出路径 | 可能性 | 预期估值 | 所需条件 | 时间窗口 |
|---------|:-----:|:-------:|:--------|:-------:|
| 教育SaaS转型 | 低/高回报 | 高 | DAU>5万+B端需求明确 | 2-3年 |
| 被游戏公司收购 | 中/中回报 | 中 | DAU>3万+月收入稳定 | 1.5-3年 |
| 被教育科技收购 | 中/中回报 | 中 | B端从demo走向签约 | 2-3年 |
| 独立运营分红 | 高/低回报 | 低 | DAU>1万可持续 | 持续 |
| 被大厂收购 | 低/高回报 | 高 | DAU>10万+品类颠覆 | 3-5年 |

**决策树：** 按DAU量级 / B端转化率 分支，不同路径对应不同的资源配置

#### 财务风控框架

**成本失控预警线（黄线/红线双轨）：**
- CAC > ¥3 (黄) / > ¥5 (红)
- 买量7日ROI < 0.5 (黄) / < 0.3 (红)
- 月成本超预算 > 20% (黄) / > 50% (红)
- 广告填充率 < 80% (黄) / < 60% (红)

**现金流断裂点：** 现金余额 / 月均净流出 = 存活月数

**止损节点（Gate制）：**
- Gate 1 (M3)：次留<20% → 终止项目
- Gate 2 (M6)：DAU<3,000或次留<25% → 停止买量
- Gate 3 (M9)：DAU<8,000或月收入<¥5万 → 考虑出售
- Gate 4 (M12)：累计亏损>¥50万且无B端意向 → 清算

#### 前瞻性预判框架

**1年财务结构预测：** 细化到M12的收入结构（IAA/IAP/B端/订阅占比）、成本结构、月盈亏

**3年财务结构预测：** DAU进入平台期，关注：
- 收入从IAA为主 → B端/SaaS为主的演变
- 净利润率从0提升到35-45%
- 买量成本占比下降，自然量+口碑占比上升

**利润拐点分析（5个拐点）：**
1. 毛利润转正（DAU>5,000）
2. 净利润转正（收入覆盖全部成本）
3. 二变现曲线盈亏（IAP/B端贡献正利润）
4. 规模效应显现（边际利润率>80%）
5. SaaS结构拐点（B端收入占比>30%）

**规模效应拐点：** 边际成本率 = 边际成本/用户 ÷ 边际收入/用户，该值大幅下降的DAU区间

#### 敏感性分析（必做）

识别对净利润影响最大的3-5个参数，分别计算±变化幅度对12个月净利润的影响：
- **🔴极高敏感度**：DAU增速、eCPM
- **🟡中敏感度**：CAC、人力成本、IAP付费率
- **🟢低敏感度**：B端签约数、订阅转化率

> 合规顾问覆盖全部法律法规维度，从版号/备案到AI监管，适用于**游戏/小游戏/IAA/IAP/教育SaaS/AI工具**等各类项目。

### 第一步：确定核心合规路线（两维决策矩阵）

开始分析前先确认两个前置问题，它们决定整个合规策略的走向：

**维度A — 项目类型：**
| 类型 | 版号/备案要求 | 典型审核周期 |
|------|-------------|------------|
| 🎮 游戏/IAA小游戏 | 无需ISBN版号，需微信资质审核1-3天 | 1-3天 |
| 🎮 游戏/IAP内购 | 必须《网络游戏出版物号》(ISBN)，6-12个月 | 6-12月 |
| 🤖 AI工具/SaaS（非游戏） | 无需ISBN版号；需ICP备案+微信认证 | 7-20天 |
| 📚 教育平台（非游戏） | 需ICP许可证+类目资质（根据所选类目） | 1-3月 |

**维度B — 内容生成方式：**
| 方式 | AI双备案需求 | 合规成本 | 周期 |
|-----|-------------|---------|:----:|
| 预置内容（无LLM） | 无需 | ¥0 | — |
| 调用已备案大模型API | 通常无需算法备案（需确认是否具舆论属性） | ¥5,000-30,000 | 1-3月 |
| 自研大模型/境外LLM | 必须完成大模型备案+算法备案 | ¥100,000-300,000+ | 6-9月 |

**维度C — 小程序类目选择（教育/AI工具类项目，最关键决策）：**

| 候选类目 | 资质门槛 | 适用项目 | 合规成本 |
|---------|---------|---------|:-------:|
| **工具** 🏆 | 无特殊资质，仅需营业执照+微信认证 | 效率工具、SaaS、管理工具 | ¥300/年 |
| **教育服务-教育信息展示** | 个人主体即可，但**不能含支付、视频、直播** | 纯信息展示 | ¥0 |
| **教育服务-教育平台** | 《增值电信业务经营许可证》+ 培训机构合作协议 | 多机构教育平台 | ¥10,000+ |
| **教育服务-在线视频课程** | 《民办学校办学许可证》或ICP证 | 培训机构/学校 | ¥5,000+ |

> **关键策略**: 教育场景的AI工具/SaaS项目，优先选择「**工具**」类目，可规避教育类目的高门槛资质要求。  
> 核心判断标准：如果产品是"辅助老师提高效率的工具"而非"提供课程/培训的服务"，就是工具类目。

### ⚠️ 合规顾问的特别警告

**AI监管是当前政策环境下最大的合规变量。** 无论项目类型，只要涉及LLM实时生成内容，需要特别向产品经理和财务总监警示：
- AI双备案（大模型+算法）周期6-9个月，远超MVP开发周期
- 使用海外未备案LLM是红线（网信办可立即下架+罚款+吊销牌照）
- 反向代理/IP伪装等规避手段同样违法
- 教育类AI项目的学生数据合规+AI监管双线风险叠加，合规成本倍增
- **推荐策略**: MVP阶段（1）国内已备案大模型API（2）老师全程确认机制（3）数据不用于训练。验证产品力后再评估是否需要双备案升级
