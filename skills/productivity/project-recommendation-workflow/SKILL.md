# 项目推荐红蓝验证工作流

## 核心规则

**不准跳过任何一步。** 每一步必须输出可验证的结论才能进下一步。

**被提名原则：** 任何方向（不管是蓝方提的还是你提的），都必须在红方质疑+数据验证通过后才能作为可行选项呈现。在验证完成前，只能回答"需要查数据"，不能直接说"能做"或"不能做"。

### 历史教训（必读）

这个技能是因为过去反复翻车才建的。Yasin点出的问题：
1. ❌ **没问限制就瞎推** — 他认为合适的跟实际条件对不上
2. ❌ **不调研就开口** — 他说过"你先搜索论证过没有"，数据验证前不准说话
3. ❌ **思路太窄** — 他是说过"不要局限在ai文字"，Hermes全能力都能用
4. ❌ **只盯着国内** — 海外平台（Fiverr等）同样有机会，不要默认排除

5. ❌ **用过期数据判断** — 平台规则变化极快：小红书2026年3月封杀AI托管账号（80万+封禁），闲鱼2026年6月经营性卖家新规。3个月前的数据可能已经失效。搜数据时必须同时查**平台最新规则**。

6. ❌ **凭空捏框架/改名已有框架** — 他已有六分身分析（project-four-persona-analysis），覆盖了深度分析层的一切。不要提出"IPO²"之类的改名版。你的六分身 = IPO的豪华精装版。你只需做接力，不用重造。

7. ❌ **混淆「决策层」「分析层」「执行层」** — 红蓝=决策选方向，六分身=分析可行性，IPO=执行节奏。三层不同功能，不要混成一个新名字。IPO是Step 6里极简的执行节奏参考，新周期开启时指导"今天该输入什么、处理什么、输出什么"，不是分析框架。你的六分身才是分析层。

8. ❌ **默认用他现有产品举例** — 分析方向/提案时，先讲通用市场、竞品、抽象方法论，不要默认拿服小助当例子说「你可以把XX集成到服小助」。等他主动说「帮我看看我的情况」再切到他的具体产品。

9. ❌ **把「蓝海」当默认结论** — 发现市场空白时，不能说「这是个蓝海」。要追问：是真没人想到（蓝海），还是有人试过但做不起来（黑海）？搜数据时必须顺带搜「XX方向 失败 为什么没做成」。

10. ❌ **混淆方法论价值和用户需求** — 方法论深不等于能卖。短视频平台用户要的是「揉碎喂嘴里的具体动作」和「明天能赚钱的结果」，不是框架。方法论是你的后台工具，前台展示的是具体结果。推荐方向时要区分：这是卖方法论，还是卖结果。

11. ❌ **不标记猜测/幻觉** — 当数据不足以支撑结论时，必须主动说「这是推断，没有数据支撑」或「这可能是幻觉，需要验证」。不要用肯定语气输出未经搜索验证的判断。

12. ❌ **理想化收入预测** — 收入预测必须打折扣。咨询类第一个月大概率0收入（冷启动挣信任）；内容类需要3-6个月起号；模板/产品靠流量转化。不要把「上线就能卖」当默认假设。

犯过以上任何一条 → 说明没读过这段。重读再继续。

## 七步工作流

```
    ┌────────────────────────────┐
    │  Step 0: 确认限制条件       │ ← 推断+提问，不瞎猜
    └───────────┬────────────────┘
                ▼
    ┌────────────────────────────┐
    │  Step 1: 蓝方首发提案       │ ← 3个候选方向
    └───────────┬────────────────┘
                ▼
    ┌────────────────────────────┐
    │  Step 2: 红方攻击验证       │ ← 质疑每个方向
    └───────────┬────────────────┘
                ▼
    ┌────────────────────────────┐
    │  Step 3: 数据实地验证       │ ← 搜索真实数据
    └───────────┬────────────────┘
                ▼
    ┌────────────────────────────┐
    │  Step 4: 铁律过滤           │ ← 红线筛
    └───────────┬────────────────┘
                ▼
    ┌───────────┴────────────┐
    │   全部淘汰？             │
    │   ↓ 是 → 兜底机制        │
    │   ↓ 否 → Step 5         │
    └─────────────────────────┘
                ▼
    ┌────────────────────────────┐
    │  Step 5: 最终推荐           │ ← 唯一方向
    └────────────────────────────┘
                ▼
        你需要同意或拒绝
        同意 → Step 6
        拒绝 → 回Step 0，调整限制条件，重来
                ▼
    ┌────────────────────────────┐
    │  Step 6: 最小行动验证       │ ← 干一单试试
    └───────────┬────────────────┘
                ▼
    ┌────────────────────────────┐
    │  Step 7: 结果反馈           │ ← 写入记忆，下次参考
    └────────────────────────────┘
```

---

## Step 0: 确认限制条件

**先推断，后提问，不瞎猜。**

先从历史记录和记忆推断已知限制。只确认不确定的：

```
1. 资金 → 已知：0
2. 时间 → 已知：看情况
3. 公司 → 已知：无
4. 英语 → 已知：不会 / 能读写
5. 愿意做 → 上次说了什么？
6. 红线 → 已知：灰色不碰、圈子不碰
7. 目标 → 这次的目标是什么？
8. 时限 → 这次多久？
```

输出格式：
```
═══════════════════════════════════════
📋 本次限制条件
═══════════════════════════════════════
已确认：___
待确认：____（如果你没说，我就问）
```

---

## Step 1: 蓝方首发提案

蓝方提出3个候选方向。每个方向必须附带：
- 方向名称
- 一句话说清做什么
- 为什么适合
- 预期月收入
- 启动时间
- 初步证据（不充分但要有一点）

蓝方必须标注：**「当前阶段：未验证提案」**

```
═══════════════════════════════════════
🔵 蓝方首发提案
═══════════════════════════════════════

【候选1：XXX】
做什么：___________
为什么适合：依据当前限制条件___
预期月收入：¥___（来源：___）
启动时间：___天
初步证据：___
状态：❌ 未验证
```

---

## Step 2: 红方攻击验证

红方对每个候选方向提出3个质疑：

1. **限制质疑** — 真的符合所有限制条件吗？
2. **证据质疑** — 能赚钱的证据在哪？真实数据还是道听途说？
3. **可行性质疑** — 一个人，0资金，0圈子，真的能做得起来？

```
═══════════════════════════════════════
🔴 红方攻击
═══════════════════════════════════════

【候选1：XXX】
├── 限制质疑：___
├── 证据质疑：___
├── 可行性：___
└── 判定：直接淘汰 / 需进一步验证 / 通过
```

**判定标准：**
- 直接淘汰 → 有明显不可突破的限制
- 需进一步验证 → 数据不足，需要实际搜索
- 通过 → 红方暂时没有致命质疑

---

## Step 3: 数据实地验证

**必须实际搜索，不能靠记忆或猜测。**

**首先**检查 `references/verified-platform-paths.md` — 之前已验证过/淘汰过的方向直接引用结论，不要重复搜索。

接着对红方判定「需进一步验证」的方向，进行：
1. 搜索该方向的真实案例和收入数据
2. 搜索该平台的准入门槛和**最新规则**（特别注意：平台内容政策变化极快，小红书2026年3月发布AI禁令、闲鱼2026年6月出台新规——过时数据会直接导致判断错误）
3. 搜索该方向是否在走下坡路
4. 提取关键数据，不要长篇复制

```
═══════════════════════════════════════
📊 数据实地验证
═══════════════════════════════════════

【候选1：XXX】
├── 搜索关键词：___
├── 真实案例：___
├── 门槛确认：___
├── 平台状态：___
├── 关键数据：___
└── 结论：可行 / 不可行
```

**验证不充分时，不准跳到下一步。**

---

## Step 4: 铁律过滤

**⚠️ 不要只局限在AI文字。** Yasin说了用Hermes全能力（文字/代码/PPT/视频/部署/设计），所有Hermes能生成的东西都是武器。

限制条件每次会变，启动时先确认当前铁律。默认铁律：

| 铁律 | 候选1 | 候选2 | 候选3 |
|------|:----:|:----:|:----:|
| 0资金能启动 | | | |
| 不需要公司 | | | |
| 不需要熟人圈 | | | |
| 30天内能见钱 | | | |
| 不限平台（国内+海外都考虑） | | | |

**铁律有一条不通过 = 直接淘汰。**

---

## 兜底机制：全部淘汰时怎么办

如果3个候选全部在Step 2/3/4被淘汰，启动兜底：

**降级到"最小可行动作"** — 不做大项目，先做一件今天能做的事来建立起点：

```
═══════════════════════════════════════
🆘 全部淘汰 · 兜底方案
═══════════════════════════════════════
当前限制下没有找到能过铁律的方向。
建议降级目标。

\[降级方案\]
不做月入1万，先做月入500。
选一个当前限制下最接近实际的方向，
今天干一单试错。

推荐最小动作：_______
```

---

## Step 5: 最终推荐

只有通过全部4步验证的方向，才进入最终推荐。

```
═══════════════════════════════════════
🏁 最终推荐
═══════════════════════════════════════

✅ 推荐方向：[唯一方向]
📋 做什么：___
📊 预期收入：___
⏱ 启动时间：___
📌 第一步行动：___
⚠️ 风险提示：___

❌ 被淘汰的方向：___
❌ 淘汰原因：___
```

**推荐后你要做决定：**
- ✅ 同意 → 进入Step 6 最小行动验证
- ❌ 拒绝 → 回Step 0，调整限制条件，重新走完整流程。不能直接从Step 5跳到别的推荐。

---

## Step 6: 最小行动验证（含IPO执行子循环）

不搞大计划，先干一单最小的。

选定方向后进入 **IPO执行子循环**，每轮循环完成一个小输出后迭代加速：

```
┌─────────────────────────────────────┐
│  IPO执行子循环（用于Step 6执行期）      │
│                                      │
│  I (Input)   今天我需要学什么/搜什么？   │
│  P (Process) 怎么拆？画什么框架？       │
│  O (Output)  今天出什么货？             │
│       ↓                                │
│  反馈 → I'（上轮输出作为本轮输入）      │
│  循环加速（越来越快）                   │
└─────────────────────────────────────┘
```

```
═══════════════════════════════════════
🎯 最小行动验证（启动轮）
═══════════════════════════════════════

行动：___（今天能做的具体动作）

[IPO本轮]
├─ I (Input)：   需要什么信息/素材？搜什么数据？学什么？
├─ P (Process)： 怎么拆解？用什么框架分析？
└─ O (Output)：  今天产出什么？（文章/视频/demo/卖一单）

时间：___（预计花费）
成本：___（0元 / 少量）
成功标准：___（什么算成了）
完成时限：___（最多3天）
```

**执行完才能进下一步。没执行=流程中止。**

---

## Step 7: 结果反馈

执行完后必须反馈结果，写入长期记忆。

```
═══════════════════════════════════════
📝 结果反馈
═══════════════════════════════════════

实际做了什么：___
花了多少时间：___
收到钱了吗：___（¥___）
问题/卡点：___
判断：继续做 / 换方向
```

Memory写入内容：
- 这次推荐的什么方向
- 执行结果如何
- 下次推荐同类方向时自动参考这个记录
