# 外部 Agent 平台拆解与蒸馏（拆 → 映射 → 蒸馏）

用途：拆外部 Agent 产品/平台（Grok Bot、ChatGPT Work、Cursor、Claude Agents…），提取可复用到自己架构的设计模式。
每个新拆解追加一节，不要新建技能。

---

## 一、通用四步

1. **抓权威源**
   - 官方打底四页：`overview`（差异点）/ `security-approvals`（人类闸门）/ `skills-routines`（可复用机制）/ `computer-and-apps`（执行环境）
   - 再补 **1 篇实际使用者长文**（工作坊拆解、官方 PM 指南）——官方给设计意图，使用者长文给**真实瓶颈**
   - 第三方转述的价格、名额、平台支持一律标「以官方页为准」，不写死
2. **落事实档案**：每条事实带来源 URL；官方自报数据必须标「团队自述、未经独立验证」
3. **映射自己（必须实测）**：见第三节清单。凭记忆写现状 = 交付废纸
4. **可蒸馏清单表**：`它的做法 | 我有什么 | 差距(✅/⚠️/❌) | 动作 | 成本`，最后挑 3 条最高 ROI 让用户拍板

**输出文件落** `~/Desktop/hermes/<产品>-distill/`，两个文件：`00-事实与来源.md`（知识库）+ `01-可蒸馏清单.md`（对照表+动作）。

## 二、回答格式（用户认可的形状）

一句话结论 → 它牛在哪（带出处的表）→ **我的现状体检（实测值）** → 最能抄的 3 条 → 反面教训（做平台时最值钱）→ 一个拍板点。
用户问「X 是不是跟你一样的」时用**对照表**（维度 | 它 | 我），不要长篇方法论。诚实标注差距等级，别粉饰。

## 三、自测清单（量自己，别凭印象）

```bash
# 批准策略（关键：默认全放行 = 与主流产品方向相反）
grep -n -A5 'approvals' ~/.hermes/config.yaml
grep -n -A3 'security' ~/.hermes/config.yaml      # redact_secrets
# 定时任务池 / 技能数
python3 -c "import json;print(len(json.load(open('/home/ubuntu/.hermes/cron/jobs.json'))))"
ls ~/.hermes/skills/ | wc -l
# Agent 矩阵有没有「禁区」字段
ls ~/Desktop/hermes/company-agents/ && grep -n -i '禁止\|不得' ~/Desktop/hermes/company-agents/16-agent-design.md
```

2026-09 实测（服务器 default profile）：approvals.mode=false / redact_secrets=false / cron 14 条 / skills 45 个 / 16 个 Agent 只有「禁止编造」类底线、**无逐 Agent 禁区字段**。

## 四、案例：Grok Bot（xAI，2026-08-11 beta，2026-09 拆）

来源：`x.ai/news/introducing-grok-bot`、`docs.x.ai/grok-bot/{overview,computer-and-apps,skills-routines-and-automations,approvals-security-and-privacy,files-and-results}`、`x.ai/bot/guides/grok-bot-for-pms`（Kevin Niparko）、tenten.co 工作坊拆解两篇。

### 产品形态
- 「always-on agents 团队」：每条 Bot 在云端有**持久电脑**（浏览器+文件系统+终端），关笔记本照跑
- 用 **Cursor 账户**登录；含在 Cursor 付费档 / Cursor Teams / 链接 SuperGrok / X Premium+
- 计费独立于 Grok/Cursor 套餐，**按周重置**
- 桌面（mac/Win/Linux）+ iOS 18+ / Android 9+

### 抄得动的机制

| 机制 | 具体做法 |
|---|---|
| **角色卡写禁区** | 官方团队里 Emily 是工程经理且「**不许自己写代码**」；招聘 Bot「不许做最终录用决定」。好的角色定义 = 能力 **+ 禁区 + 何时停下** |
| **Skill / Routine 分离** | skill = 怎么做（跨 Bot 共享，`/` 引用）；routine = 谁在何时跑（绑定拥有者 Bot，上限 50 条，每条留最近 20 次运行记录，删除不可撤销） |
| **一条好 skill 写 6 件事** | 何时用 / 需要什么输入与权限 / 工作顺序 / 怎么验证结果 / 交付什么 / 什么必须人工批准 |
| **示范学习** | Teach a task：录屏你操作（≤10 分钟，不录麦）→ 自动生成 skill **草稿** → 人工补决策规则、失败处理、批准边界 |
| **排程三振法则** | 先跑一次真实任务 → 第二次确认修正能保留 → **第三次才开排程**。「第一次就排程，只会把模糊需求放大」 |
| **no-data / stale-data 策略** | 源挂了必须报失败，**不许用旧数据凑**；重试要幂等；部分完成要说明报到哪 |
| **人类闸门分级** | 必须批准：外发消息/发布/采购转账/删除覆盖/改权限/生产变更/接受法律条款。`Require Approval` **优先于** `Always Allow`；规则要**窄**（官方明令禁止「允许浏览器里的一切」） |
| **敏感步骤接管** | 密码/2FA/CAPTCHA/支付 → 人接管电脑只做那一步；secure secret request 的值**不进 transcript、不给模型看** |
| **本机执行三档** | 总是问 / 总是允许 / 永不允许。默认 **Ask every time**；无特殊理由用 Never allowed |
| **注意力清单** | 不看你的待办，看**真实行为**（回了谁的信、进了哪个会、动了哪个文档）反推当下注意力；用途①噪音过滤器 ②对比「我说重要」vs「我实际花时间」 |
| **Agent 不该吵** | 没事不许制造通知；只有需要决策才回来 |
| **退出清理 6 步** | 暂停 routine → 登出网站 → 卸 connector 并撤销源授权 → 清 /workspace 敏感文件 → 隐藏/删 Bot → 删账户。**删 Bot 不等于删文件与浏览器会话** |

### 反面教训（做平台时最值钱）

- **共享电脑不是安全边界**。官方原文：`The screens are separate work surfaces, not separate security boundaries.` / `Do not use separate Bots as a security boundary.`
  → 同账户下文件、浏览器 cookie、登录会话、命令行凭证全共享。**「你是设计师」这种角色提示约束不了浏览器会话**。
  → 映射到自己：多个 Agent 挤在同一个 Linux 用户下，同样没有隔离。真要隔离得分用户/容器/独立凭据。
- **瓶颈不是模型能力，是权限与验收**。护城河 = 权限分级 + 交接契约 + 验收/审计。
- 能推断注意力的 Bot 必须读极广工作足迹 → **观察与执行分两阶段开放**；导入前先答三问：哪些源可读、保留多久、清单能否触发动作。
- 「占内部合并 PR 两位数百分比」= 团队自述，无第三方验证，不可当普遍生产力承诺。

### 七步导入法 + 交接契约模板

1 定义**一个结果**（别写「帮我把产品做了」）→ 2 建**一个负责人**（端到端，真需要专才再加）→ 3 写**交接契约** → 4 **读写权限分离**（能读 ≠ 能回、能改）→ 5 放**人类闸门** → 6 跑**一次真实工作**（真题目真工具）→ 7 **量测后才排程**（接受率/退件原因/人工修订时间/权限例外/恢复成本）。

```
目标：<一个具体产物>
输入：<来源，只读>
输出：<放哪里，含哪些必附字段>
交接：<何时标记哪个 Bot>
停止条件：来源矛盾 / 需登录新工具 / 准备外发 / 会花钱 / 会删数据 / 要改生产环境
禁止：不得捏造引用、不得自行发布、不得合并代码
```

每次扩张前问 4 题：能读什么？能写到哪里？哪个动作影响外部世界？出例外时谁决定？答不上来就排程 → 错误只会更快累积。

## 五、我方可复用的三条（首次拆解就落地）

1. **给每个 Agent 补「禁区」三行**（能力之外的反向定义）
   ```
   禁止：<明确不该做的 1-3 件事>
   停止条件：<遇什么必须停下问人>
   越权默认：<拿不准 → 不改数据 / 不发送 / 只出草稿>
   ```
2. **装一组窄批准规则**：只锁 5 类（外发消息 / 花钱 / 删除覆盖 / 生产变更 / 公网发布），其余放行不牺牲速度。
3. **示教学习变通版**（Hermes 无原生 teach-by-demonstration）：用户操作一遍录屏 → 我看录屏+日志 → 产出 skill 草稿交用户审。候选流程：罗盘盯盘 / 达人广场采集 / 飞书发内容 / 剪映出片。
