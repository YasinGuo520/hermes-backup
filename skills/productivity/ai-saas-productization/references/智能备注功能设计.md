# 智能备注功能设计（AI客服Smart Notes）

> 适用场景：AI客服SaaS中，AI不只回复，还需要识别客户需求并记录

## 一、需求背景

客户在咨询中经常提出需要商家操作的请求：

```
客户：「帮我换成红色M码」
客户：「改成顺丰发货，加急」
客户：「跟上次买的一样的尺码，不同颜色」
客户：「备注一下，放门卫室不要打电话」
```

这些需求AI无法直接完成（涉及资金/订单修改），但可以**识别→提取→记录→提醒商家处理**。

## 二、功能分级

| 等级 | 功能 | 实现难度 |
|:----|:-----|:--------|
| **L1（推荐MVP做）** | AI识别需求→提取结构化信息→写入备注表→商家看板展示 | ⭐ 容易，1天 |
| **L2（V2可加）** | 自动调用平台订单备注API写入订单（抖店/拼多多有此API） | ⭐⭐ 需平台支持 |
| **L3（暂不）** | AI直接改订单（改地址/改SKU/改价格） | ❌ 风险高，涉及资金 |

## 三、数据模型

```python
class CustomerNote(Base):
    """客户备注表"""
    __tablename__ = "customer_notes"
    id = Column(Integer, primary_key=True)
    tenant_id = Column(String(64), index=True, nullable=False)
    platform = Column(String(20), nullable=False)  # doudian/pdd
    order_id = Column(String(64), nullable=True)   # 平台订单号（如有）
    customer_id = Column(String(64), nullable=False)
    note_type = Column(String(20), nullable=False)  # 改尺码/改地址/改快递/其他
    content = Column(String(500), nullable=False)   # 提取的备注内容
    original_message = Column(String(1000))         # 原文
    status = Column(String(20), default="pending")  # pending/done/ignored
    created_at = Column(DateTime, default=datetime.now)
    processed_at = Column(DateTime, nullable=True)
```

## 四、AI识别逻辑

在消息处理器中，AI回复后再加一道判断：

```python
async def process_message(message):
    intent = classify_intent(message)
    reply = await generate_reply(message, intent)
    # 判断是否含备注需求 ← 新增
    note = extract_customer_note(message, reply)
    if note:
        save_note(tenant_id, note)
        # 看板标记 ⚠️ 待处理
    return reply
```

### 备注需求识别规则

| 关键词 | 备注类型 | 优先级 |
|:------|:--------|:-----:|
| "换" + (颜色/尺码/款式) | 改规格 | 高 |
| "改地址"、"换地址"、"送到" | 改地址 | 高 |
| "顺丰"、"加急"、"快递" | 改快递 | 中 |
| "门卫"、"放"、"代收" | 放置说明 | 中 |
| "查物流"、"到哪了" | 物流查询 | 低（AI直接回即可） |

**核心逻辑：** 不是把所有"不寻常"的消息都转人工，而是：
- AI正常回复（维持3秒响应）
- 但额外提取备注需求记录到系统
- 商家在后台看一眼就知道需要处理什么

## 六、与转人工的边界

| 条件 | 走智能备注 | 直接转人工 |
|:----|:---------|:----------|
| 客户明确说操作需求 | ✅ AI回+记录 | 走备注即可，不用转 |
| 连续3次追问未解决 | 先记录 | ✅ 转人工 |
| 涉及退款/投诉/赔偿 | 记录 | ✅ 转人工（优先） |
| 客户发图片（售后） | 记录 | ✅ 转人工 |
| 只是问问题（尺码/面料/物流） | ✅ AI回，无需备注 | 不用转 |

## 七、扩展备注类型：插件自动生成的打包备注

除客服对话中的手动备注需求外，**插件也可以自动生成备注**，例如雨刮器车型匹配插件：

### wiper_pick 类型备注

```python
note_type = "wiper_pick"   # 仓库打包专用备注类型
note_content = "【雨刮打包】丰田 8代凯美瑞/凯美瑞双擎 (2018-2023) | 主驾26寸 副驾20寸 | U型 | SKU: U-2620"
```

**触发时机：**
1. **聊天实时** — 客户发"2018款凯美瑞雨刮" → 插件匹配 → 同时写 wiper_pick 备注
2. **Webhook异步** — 平台推送订单备注"哈佛H6雨刮" → 本地匹配 → 零API成本
3. **批量补扫** — 手动调用 `/api/notes/process-wiper` 扫描所有待处理备注

**特点：**
- 不消耗LLM token（纯本地JSON关键词匹配，2500条内存加载）
- 自带客户名+订单号上下文，方便仓库定位
- 看板可筛选 `note_type=wiper_pick` 显示所有待打包单

### 备注类型矩阵

| note_type | 来源 | 谁处理 | 生命周期 |
|-----------|------|--------|---------|
| size_change / address / delivery / refund | 客服对话AI提取 | 客服/运营 | pending → done |
| order_remark | 平台订单备注Webhook | 客服/运营 | pending → done |
| **wiper_pick** | **插件自动匹配** | **仓库打包人员** | pending → packed |
| other | 客服对话AI提取 | 人工判断 | pending → done |

## 八、对定价的影响

备注功能**不额外计费**（属于基础能力），但：
- 提升商家效率（不用自己翻聊天记录找需求）
- 是防止客户流失的功能
- 可以作为差异化卖点
