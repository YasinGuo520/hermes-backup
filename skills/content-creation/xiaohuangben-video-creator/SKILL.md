内容类型缺省：默认 `晒过程`（带货最常用）

### 区块5：风险预警

| 风险点 | 说明 | 应对 |
|--------|------|------|
| 实测产品画质 | I2V模型生成的产品细节可能有偏差 | 必须用实拍产品照，不要AI生图 |
| 配音时长>视频 | 配音太长视频不够长 | 先测配音时长再算视频截取长度 |
| 合成后无声音/声音太小 | 混音后音量降至-22dB，播放器低音量时听不见 | 合成后用 `ffmpeg -i out.mp4 -af volumedetect -f null - 2>&1 | grep mean_volume` 检查。正常应在-12~-18dB。偏低时用 `[1:a]volume=3.0` 提声再混 |
| 内容合规 | 内衣类"荷尔蒙"容易触发审核 | 镜头控制在产品展示，不要过度性感 |
| 平台限流 | 带货视频含导购话术可能被限 | 开头3秒必须有价值，不要纯催单 |

## 执行前必做：图片预处理

### ⚠️ 用户给图后，先做3件事

```
① 检测水印
   → vision_analyze 识别全图：58pic / tao.hoos / 视觉中国 / 随机字符串水印
   → 有则先PS去水印，别直接上传百炼（I2V会保留水印文字）
   → 去水印方法见 chaoke-i2v-product-video 的 references/watermark-handling.md

② 检查图片格式
   → file <path> 检查真实格式。HEIF/HEIC图片（.jpg实际是HEVC格式）不能被PIL/Python直接读取
   → 修复: sips -s format png 源文件 --out 目标.png
   → Pillow不支持HEIF，别尝试用PIL打开，先 sips 转码

③ 判断是否为模特实拍
   → 如果已经是真人模特穿着 → 跳过百炼生图，直接走I2V动效
   → 如果是平铺/挂拍图 → 先百炼 qwen-image-2.0-pro 生成模特上身图（¥0.50/张），用户确认后再I2V
   → 组合图（如正面+背面纵向拼图）→ 用PIL crop拆分成独立图片
```

### 对比测评类（双产品）的I2V管线差异

晒过程→测评产品涉及 **两个产品A/B对比**，与单产品I2V不同：

| 环节 | 单产品标准流程 | 双产品对比流程 |
|------|--------------|--------------|
| 上传 | 1张图 | 2张图（各自上传，得2个oss URL） |
| I2V生成 | 同一张图出3条 | 产品A出2条，产品B出1-2条 |
| 合成 | 3段→xfade→成片 | 3-4段→xfade→成片 |
| 成本 | ¥6-9（硅基3条） | ¥6-8（硅基3-4条） |

**分镜对应关系：**
```
镜1 (0-3s) 产品A亮相 ← I2V 慢推进(产品A)
镜2 (3-5.5s) 产品A细节 ← I2V 上移(产品A)
镜3 (5.5-8s) 产品B亮相 ← I2V 慢推进(产品B)
镜4 (8-10s) 结果+CTA ← I2V 定格/环绕(产品B)
```

### 品牌名注意

`build_final.py` 的 `subs` 区硬编码了 `"CHAOKE 潮客摄影"`。每次跑新客户的视频，**必须把字幕文字改成实际品牌名**。不要出现别人的品牌。

### 用户说清了哪件是哪件吗？

**实测教训：用户经常会搞反产品对应关系。** 给图时说「产品1是89元，产品2是899元」但实际情况可能相反。
- 用 `vision_analyze` 确认两张图的款式/颜色
- 在分镜脚本中明确标注「产品A=89元黑色款」「产品B=899元粉色款」
- 发方案时让用户确认价格与款式对应正确再执行

### I2V输出比例不可控

百炼 happyhorse-1.1-i2v 的 `--ratio 9:16` 参数不保证生效。输出分辨率可能是960×960（正方形）或1090×844（横屏）。
- **不要在分镜里写「I2V会输出720×1280」**。写成「I2V输出后ffmpeg统一scale+pad成竖屏」
- 合成时的标准处理：`scale=W:H:force_original_aspect_ratio=decrease,pad=W:H:(ow-iw)/2:(oh-ih)/2`
- 几段I2V分辨率不一致不用慌，ffmpeg xfade会统一处理

### 先出配音再算视频长度

**不要先估算文案字数再假设视频时长。** 流程必须是：
```
① 生成文案
② edge-tts出配音
③ ffprobe测配音时长
④ 用配音时长反推每段I2V的截取长度
```
本skill输出的建议时长只是参考，执行时以实际配音时长为准。
