# 把 AI agent CLI 变成可脚本调用的后端

**触发**：用户问「某某 AI 工具的会员还能用来干嘛」「能不能自动调它」「把 X 接进流水线 / 让 Hermes 用上 Claude」，或需要从服务器/脚本驱动另一台机器上已登录的 AI 桌面应用。

## 铁律

0. **只读侦察随便做，任何「真实调用」都是写操作——动手前先拿授权。** 在用户账号里跑 `new-conversation` 这类命令 = 写操作：它在账号里建对象、烧付费配额、在服务端留下**删不掉**的请求记录。技术上再安全也是写。
   - **顺序：查 → 汇报 → 等明确同意 → 再跑。** 只读侦察（`--help`、列进程、读配置、零配额探针）跑通 ≠ 授权往下跑真实调用。
   - 用户对此零容忍（原话：**「你违背了没有我确认就自动操作的原则」**）。授权你远程维护机器 ≠ 授权你在他的付费账号里创建东西。「一路查到能调通就顺手验证一下」是这个坑的固定剧本。
   - 已经跑了：**主动交代全量残留**（跑了什么、哪档模型、代价多大、账号里多了什么），再按「越界后清理」一节抹掉。
1. **只调官方二进制，不碰 OAuth token 文件。** 官方支持的边界是：外部进程通过 stdin/stdout 调用官方 CLI，消耗同一账号额度。官方**明确不支持**的是：从磁盘抠 OAuth token 给第三方客户端复用、直连产品后端。走这条 = 封号路径，用户账号价值远大于省下的钱。token 只从**运行中进程**的参数/环境里读（很多是每次启动随机生成、只存在于进程 argv），且只用于给官方二进制设环境变量——不落盘、不外传、不进对话。
2. **探针只用零配额命令；真实调用要授权。** 连通性验证一律用**只读且必然查不到的**调用（如 `get-*-metadata <不存在的ID>`）——它不建对象、不烧配额。真实任务调用**不是**探针：每次试错都在烧用户的付费配额，还会在账号里留痕。
3. **端口和环境变量名从进程/二进制里读，不要猜。**
   - 端口：`lsof -nP -iTCP -sTCP:LISTEN -a -p <PID>`
   - 它认哪些环境变量名：`strings -a <二进制> | grep -oE "<产品前缀>_[A-Z_]*" | sort -u`
4. **macOS 没有 GNU `timeout`**（报 `command not found: timeout`）。包住可能长驻的 CLI 调用：
   `(cmd > /tmp/o 2>&1 & P=$!; sleep N; kill $P 2>/dev/null); cat /tmp/o`
5. **GUI 应用形态的 CLI 依赖宿主进程活着。** 这类 "CLI" 常只是 1 行 shell 包装器，exec 到桌面 App 内的语言服务器（先 `cat` 那个包装器，它会直接告诉你真身和子命令）。所以：宿主 App 必须在跑 + 目标机没睡眠 + 代理在线。Tailscale 显示 `offline` = 什么都做不了，**先让用户唤醒机器**，别在那边反复重试。
6. **非 TTY 输出坑**：这类 CLI 常把最终回复只渲染到 TTY，管道/重定向时 stdout 为空但**退出码仍是 0**。成功判据必须是「退出码 0 **且** 内容非空 **且** 含预期标记」，只看退出码 = 半夜静默失败。需要时用伪终端包一层（macOS `script -q /dev/null <cmd>`；Linux `script -qec '<cmd>' /dev/null`）。

## 封号红线：别接流水线（实证，不是理论风险）

用户自己的判断是对的：**把订阅的模型反代出去 / 抠 token 复用，是已经大规模执行过的清洗，不是「可能被 ban」。**

| 事实 | 内容 |
|---|---|
| 触发行为 | 第三方工具（OpenCode / OpenClaw 一类）复用产品 OAuth token，伪装成官方客户端调模型 |
| 报错 | `403 PERMISSION_DENIED` + `disabled in this account for violation of Terms of Service` |
| **连带封禁** | 不只该产品，**Google AI Studio、GCP 项目创建权限一起被回收** |
| **付费用户照封** | 论坛有 Google AI Ultra 家庭套餐订阅者被封 |
| 无预警 | 「no warnings, strikes, or temporary bans」，直接永封 |
| 申诉 | 基本无效；影子封禁（配额显示可用、实际调用失败）**不可恢复** |
| 判定依据 | **请求模式**，不是工具本身：人工触发/离散任务 = 正常；7×24 自动化、高频、并行代理 = 触发风控 |

结论（直接讲给用户，别说成「有风险，你自己决定」）：

- **「接进流水线」本身就是问题，换哪种调用方式都一样** —— 即使用官方 CLI，无人值守高频自动化也是被判定封号的特征模式。
- 反代 / 包成 OpenAI 兼容 API：**绝对不做。**
- 官方二进制 + 本地进程调用：踩灰线（凭证取自进程、接口无公开文档），**别做成常驻/cron/网关**。
- 人工用 IDE + Remote Control、偶尔跑单次任务：**这才是包月订阅的正确用法。**
- 真要自动化流水线：走**按量付费的官方 API**，合法、成本可预测、无封号风险。

**风险收益比**：省下的是几十块 API 费；赔上的是**主力 Google 账号 + Gmail/Drive/AI Studio/GCP + 已付会员费**，且申诉无门。

## 步骤

1. 盘清目标机：装了什么、在不在跑、登录了没（进程 + 配置目录 + 版本号一起看，一次 SSH 批量取回）。
2. 找入口：产品配置目录下的 `bin/`、App 包内 `Resources/bin/`。**先 `cat` 可疑的启动器脚本**再动手。
3. `<cli> --help` 拿子命令全集（用铁律 4 的包法跑）。
4. 跑**探针阶梯**（第 5 步之前必做）：一条零配额命令区分「连不上 / 端口错 / 缺凭证 / 认证通过」四层。**业务层错误码 = 认证已通过**，这是成功信号不是失败。
5. 凑齐环境变量（地址 + 凭证 + 项目/租户 ID）。**到此为止：先向用户汇报已查明的结论并拿到同意**，再跑最小真实调用、记下返回的会话/任务 ID。
6. 验证能否取回模型输出——**这一步决定它是「能当模型后端」还是「只能远程下发任务」**。没验证通之前，不许对用户说「已经接进流水线了」。

## 越界后清理（已经在用户账号里建了东西）

**先枚举所有残留类别，再动手删**——宿主 App 有索引表，UI 里的条目来自它，删掉工作文件它照样显示。一次只读命令列全，别边删边找：

| 类别 | 典型位置 |
|---|---|
| **App 索引行** | sqlite 表（如 `conversation_summaries`）→ 必须 SQL `DELETE` 那一行，只删文件没用 |
| 本体文件 | 每对象一个（`conversations/<id>.db`） |
| 附属目录 | `annotations/<id>.*`、`brain/<id>/`（工作目录/轨迹） |
| 临时文件 | `/tmp/*` 你建的中间输出 |
| 常驻项 | LaunchAgents / crontab / 新装二进制 → 确认**零新增** |
| shell 历史 | `~/.zsh_history` |
| 日志 | **只报告不改**（混着用户正常记录且会轮转），让用户决定 |

删完**等几十秒再复查一次**（App 在跑，可能把内存态写回索引表），逐项给验证输出。最后**明确交代删不掉的**：服务端请求记录、已消耗的配额。

清理完不做额外动作（别替用户重启 App、别改配置）；要动先问。

## 回报节奏（用户偏好，硬要求）

这类反向工程天然是多轮（进程 → 端口 → 凭证 → 试跑）。**每 2-3 轮给一次一句话进度 + 当前已确证的结论**，不要闷头连跑十几轮。

用户中途问「你是在干嘛」= 汇报粒度太粗了。立刻切成三段式回报：**我在干 X / 已确证什么（附证据）/ 还差什么**，不要再补一轮调查才回话。

消耗了配额要主动交代：跑了什么、用了哪档模型、代价多大、账号里多出了什么残留（如新建的会话）。
