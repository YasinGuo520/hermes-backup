# 评审另一个 AI 的结论/建议：先证明它读的是哪份产物

**触发**：用户贴来 Antigravity / Claude / Codex / 别的 agent 的「现状分析 + 改进建议」问「你怎么看」；
或某个 agent 报告「系统 X 现在是 A」而你被要求据此改代码、花钱、写计划。

## 铁律一：先定「它读的是哪份」，再读它写了什么

同一系统常有多份副本，而且**旧的那份看起来完全正常**：迁移后旧目录没删（`~/Desktop/Hermes` 停着
迁移前的整棵源码）、`~/Desktop`/`~/Documents` 受 TCC 保护只有 GUI 进程能读、静态导出版 vs 本机运行版、
`.bak-*` 备份、git worktree、服务器上 `/var/www` 的旧构建产物。

**它读的是副本，它列的「现状问题」就已经不存在。** 照它改 = 重造已完成的功能，还会推翻之前
踩坑修好的东西（防自激回环、防幻觉、削静音这类都是修过一次就不该再动的）。

判定只用**元数据 + 符号存在性**，不必读代码内容（一条命令就够）：

```bash
stat -f '%z %Sm %N' <被评审的那份文件>       # macOS；Linux 用 stat -c '%s %y %n'
stat -f '%z %Sm %N' <活版同名文件>
ls <活版目录>/<只在新版出现的新文件>          # 存在性
grep -c '<新版才引入的符号>' <被评审的那份>   # 0 命中 = 它读的是旧版
```

- 最强实锤：被评审那份的**字节数与某个 `.bak-*/baseline` 逐字节相同** → 读的就是存档。
- 结论要给**对照表**（它读的那份 vs 活的那份：字节、mtime、新版才有的文件/符号是否命中），
  不要只说一句「它读错了」——用户要的是证据链。
- 先查「活版到底在哪」：`ls` 候选目录 + 看一眼正在跑的服务/端口，别默认它引用的路径就是活路径。

## 铁律二：逐条判「已做 / 真缺口」，不做整体接受或整体否定

把它列的每条做成表：`它说 → 真相（在哪、谁做的、符号/端点证据）→ 还差什么`。

- 已存在的：明写「照它做 = 重造 + 有回退风险」，并指出活版里那个具体符号/端点（可查证）。
- 真缺的：才谈代价（改哪个文件、动多少行、会不会碰到音频/权限/发布链），以及值不值得现在做。
- 活版能力清单要能一句话背出来（「打断、逐句流式 TTS、光点联动、dpr 封顶都已上线」），
  这样才不会把已完成的东西当新需求重提。
- 用户要的是**判定 + 代价对比**，不是可能性；「值得试试」这种话等于没答。已给 A/B/C 时只在里面选。

## 铁律三：查证有预算 —— 最便宜的决定性一条先跑，跑完先出结论

- 一条命令能定性的先跑；**结论一旦成立就先回复结论**，次要细节（某段 UI 逻辑在不在旧副本里、
  小数点后第三位）等用户要了再补。
- 别在已能下判断之后，再花一轮长取证去磨次要论点。Yasin 会直接问「你要看这么久吗」——
  那是「已经太慢」的信号：立刻给已确证的判断 + 还差什么，而不是解释为什么还在查。
- 贵路径（借 GUI Hermes 的 API server 读受 TCC 保护的目录、让另一个模型二次解读）单次很贵
  （实测一次 ~50K prompt tokens）：只用来答**决定性问题**，绝不连跑两次。

## 反向：让别的 agent 复审活系统时，先把坑堵上

派活/给提示词时写明：

1. **活产物的绝对路径**（「活代码在 `~/apex-src`；`~/Desktop/Hermes` 是迁移前旧副本，别读」）；
2. 「**先立基线**（跑一遍 get 现状/列文件/读版本）再提改进」；
3. 「报告里给出你读的路径 + 字节/mtime」，这样它的结论自带可验证的坐标。

不写这三句，下一次它还会读旧副本，你还要再判一次。

## 常见陷阱（都实测过）

- **把 agent 的自我总结当证据**：取证类提问必须写「原始输出贴回、别总结」，否则拿回的是它的叙述，
  而不是命令输出——后面所有判断都建在二手转述上。
- **把「说得有条理」当可信度**：文案专业度 ≠ 读的是活产物。分点清晰、术语准确、结论却基于
  十天前的存档，这种报告最容易骗过人（也最容易骗过用户）。
- **ssh 读受 TCC 保护的 Mac 目录**：报 `Operation not permitted`，随附的 `total 0` 不是「空目录」。
  只有 GUI/launchd 上下文有权限 —— 借用 GUI 侧 Hermes 的 API server 的正确姿势（含 prompt 要透明、
  别用「你是只会执行命令的机器人」这类会被拒的措辞）见 `mac-local-voice-ui-fix` 的 TCC 一节。
- **手拼 JSON / 转义**：prompt 里带 `\|`、多行内容时，shell 里 `curl -d @- <<JSON` 会被 API 判
  `Invalid JSON in request body`（白跑一轮）。写成 `.py` 用 `json.dumps` + `urllib`，scp 过去再跑——
  现成脚本 `scripts/ask-gui-hermes.py`（scp 到 Mac 后 `python3 … "cmd1" "cmd2"`，自带只读+别总结的
  prompt 模板，并回报本次 token 用量）。
- **在报告里写「现状」却不给坐标**：自己回复时也要带上路径/字节/mtime，让用户能自己复核。

## 交付格式

1. 一句话判定（「它读的是 X 之前的旧副本，4 条里 2 条早就做完了」）；
2. 证据对照表（它读的那份 vs 活的那份，含具体字节/命中数）；
3. 逐条判定表（已做 / 真缺口 / 代价）；
4. 明确建议 + 一个当天能做的动作（例如「给它补一句活路径，让它重看一遍」）。
