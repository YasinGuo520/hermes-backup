# 电商利润表自动分析 (E-commerce P&L Pipeline)

## 何时使用

- 用户说"帮我算算这个月赚了多少钱"或"自动算利润表"
- 用户给了一个电商项目文件夹，里面有各平台销售数据、费用表、进销存
- 数据在本地Excel/CSV里（不是上市公司公开财报）
- 多平台经营：抖音小店 + 拼多多 + 淘宝 + 京东

## 前提条件

```bash
pip install openpyxl xlsxwriter 2>&1 | tail -3
```

`markitdown` 可选（读Excel结构用），但实际数据提取推荐直接用 `openpyxl`。

## 核心流程

### 第一步：数据源扫描

先扫项目目录，识别所有数据文件类型：

```bash
search_files(path="/项目路径", pattern="*.xlsx", target="files")
search_files(path="/项目路径", pattern="*.csv", target="files")
```

### 第二步：按平台分类数据源

| 平台 | 典型文件 | 关键字段 |
|------|---------|---------|
| **抖音** | 月销售CSV（抖音小店导出） | 动账金额, 平台服务费, 佣金, 订单退款, 免佣金额, 订单实付应结 |
| **抖音直播** | 月总数据.xlsx（含主播维度） | GMV, 消耗(千川投流), ROI, 退款金额 |
| **抖音千川** | 消耗TOP素材.xlsx | 广告消耗, 展示, 点击 |
| **拼多多** | 刷单费用.xlsx | 直通车, DSR补单, 评价补单, 快递助手, 活动保证金 |
| **拼多多** | 快递充单.xlsx | 快递费用 |
| **淘宝** | 盈亏ROI自动计算表格.xlsx | 如已有计算表可直接用 |
| **京东** | 营销对账CSV | 营收, 费用 |
| **进销存** | 出入库管理系统.xlsx | 入库数量, 出库数量, 库存盘点; 产品资料表应有单价字段 |

### 第三步：P&L 字段映射（核心）

抖音销售CSV字段 → 利润表科目：

```
订单实付应结             → 营业收入
- 平台服务费             → 平台费用
- 佣金                   → 推广佣金
- 订单退款               → 退款扣减
- 运费实付               → 运费成本
= 净收入
- 产品成本 (出库数量×单价) → 营业成本
= 毛利
- 千川广告消耗            → 广告投流费
- 刷单费用               → 刷单成本
- 快递费                 → 物流费用
- 人工/房租/办公          → 运营费用
= 净利润
```

### 第四步：读数据（用 openpyxl，不要 markitdown）

```python
import openpyxl

# 读抖音CSV
import csv
with open('xxx.csv', encoding='utf-8-sig') as f:
    reader = csv.DictReader(f)
    for row in reader:
        pass  # 提取字段

# 读进销存Excel
wb = openpyxl.load_workbook('xxx.xlsx', data_only=True)
ws = wb['入库明细表']
for row in ws.iter_rows(min_row=3, values_only=True):
    pass  # row[1]=日期, row[2]=产品名, row[7]=数量
```

### 第五步：识别数据缺口

常见缺口：
- **产品成本单价**（进销存产品资料表的"单价"字段常为空）→ 需要用户提供
- **人工/房租**等运营费用通常不在此文件夹 → 估算或询问
- 抖音CSV只含平台扣费，不含直播间投流费（千川消耗在直播汇总表）

### 第六步：输出利润表

用 openpyxl + xlsxwriter 输出结构化利润表到 `~/Desktop/hermes/<项目名>_利润表.xlsx`。

## 用户偏好（中文电商场景）

- 利润表用中文科目名
- 按月输出（如果数据跨月）
- 多平台合并一张表（分平台列示+合计列）
- 同时输出毛利率/净利率/费用率

## Pitfalls

- **产品成本单价经常缺失**——进销存模板的"产品资料表"单价字段常空白。必须问用户要，不要编造
- 抖音CSV编码是 `utf-8-sig`（BOM），部分列用 `utf-8` 会报错
- 抖音CSV明细是订单级数据，量可能很大（月均数千行），归纳汇总时用pandas或逐行累加
- 平台服务费在抖音CSV里是**负数**（出账），不要重复扣减
- 免佣金额在抖音CSV里是正数（平台返还），应加回
- 拼多多刷单费用表结构不统一（有的日期列有时间戳，有的是纯日期），注意格式转换
- 进销存的数量字段可能有 `#N/A` 错误值，openpyxl `data_only=True` 读出来是 `None`，需跳过
- **多平台口径不统一**：抖音的"GMV"=实付+平台补贴（含未结算），利润表应取"订单实付应结"（已结算口径）

### ⚠️ 抖音CSV退款处理（常见陷阱）

`订单退款` 列的值是**负数**（如 `-89.9`），`动账方向`=出账。处理时：

```python
refund = abs(float(row.get('订单退款', '0'))) if row.get('订单退款') else 0
```

不要用 `if refund > 0` 判断——负数永远不通过。出账交易中"权益保险"（0.5-1元/笔）是平台扣费，不是退款。

### ⚠️ 京东营销对账表 ≠ 销售额

京东的"营销对账"CSV文件只有优惠分摊字段（京东承担金额、商家承担金额），不含实际订单售价。**无法从这种文件提取营收。** 需要用户提供京东结算单（含订单实付金额），或从京东商家后台导出完整订单报表。

```
# 京东营销对账表列结构（仅供识别，不可用于营收计算）：
订单编号 | 下单时间 | 商品编号 | 商品名称 | 数量 | 优惠类型 | 优惠券名 | 京东承担 | 商家承担 | 政府承担
```

### ⚠️ 拼多多费用表"汇总行"重复计算

拼多多费用表末尾有一行日期 = `汇总` 的数据行，值等于前文各行合计。遍历时必须跳过：

```python
date_val = str(row[0]).strip()
if not date_val[:4].isdigit():   # 不是日期开头则跳过
    continue
```

### ⚠️ 进销存数量列索引

openpyxl 读出入库管理的 `iter_rows()` 返回 tuple，**数量在 col 9（0-indexed）**，不是 col 8：

```python
qty = row[9] if len(row) > 9 and isinstance(row[9], (int, float)) else 0
```
