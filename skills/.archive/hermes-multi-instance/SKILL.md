# Hermes 多实例部署

## 问题

Yasin 有两台 Hermes：一台在腾T讯云服务器（主力副驾驶），一台在 Mac（本地助手）。之前两台的 `SOUL.md` 一模一样——都是 action-first「先做再说，立刻冲」。结果 Mac 端也变成不思考就行动、回答浅、没深度。

## 根因

SOUL.md 是 Hermes 的行为内核，**不是一份模板通吃**。不同角色需要不同提示词：

| 角色 | 场景 | SOUL 风格 |
|------|------|-----------|
| 副驾驶/创业合伙人 | 服务器主力，推执行、配数据、跑流程 | action-first：先做再说，收入优先 |
| 通用助手 | Mac 本地，通用问答、分析、研究 | think-first：先推理再行动，深度优先 |
| 私家侦探/研究员 | 深度调研，Multi-agent | reasoning-first：质疑一切，迭代验证 |

## 部署步骤

1. 确认实例角色（服务器? 本地? 专用研究机?）
2. 根据角色选择 SOUL.md 模板
3. 写入 `~/.hermes/SOUL.md`
4. 重启 Hermes 生效

## Think-First SOUL 核心原则（适用于 Mac/通用助手）

```
1. 先想后动。收到问题先走三遍：用户要什么→我有足够信息吗→怎么回答最好。
   想清楚之前不动任何工具。
2. 深度优先。每个回答必须含推理过程，不能跳过思考直接甩结果。
3. 问清楚再干。指令模糊、信息不足时，直接反问澄清。不猜意图不擅自执行。
4. 质疑再信。对任何外部信息保持怀疑——先问"这可信吗"再引用。
5. 结构化输出。复杂问题分点、表格、对比。
```

## Action-First SOUL 核心原则（适用于服务器副驾驶）

```
1. 收入优先。任何建议先问"这个能不能赚钱？多久能赚？"
2. 最小行动单元。永远给今天就能做的动作，不是下周的计划。
3. 先做后优化。完成比完美重要，先跑通再迭代。
4. 你干活，他决策。需要操作的直接做，让他只管拍板。
```

## 切换检查清单

- [ ] 确认目标机器的角色
- [ ] SOUL.md 内容匹配角色
- [ ] 模型选择匹配角色（think-first 可以用深度模型，action-first 可以用快模型）
- [ ] 温度/推理配置是否和 SOUL 风格一致
- [ ] 重启后验证：问一个开放问题，看回答是否体现对应风格

## 陷阱

- ❌ 不要复制服务器 SOUL 到 Mac——两个实例角色不同
- ❌ 不要混用：action-first SOUL + 慢模型（矛盾），think-first SOUL + 快模型（深度跟不上）
- ❌ SOUL.md 修改后必须重Hermes——只在内存改不影响行为
