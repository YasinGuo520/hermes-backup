# 竞品深度调研方法论

## 一、调研的七个维度

### 1. 公司基本面

| 维度 | 信息源 | 关键看什么 |
|:----|:--------|:----------|
| 工商信息 | 天眼查/企查查 | 注册时间、注册资本、实缴资本、法人 |
| 融资情况 | 投资界(pedaily.cn)、36氪、IT桔子 | 轮次、金额、投资方（判断背景实力） |
| 团队背景 | 官网、知乎、媒体报道 | 创始人履历、核心团队出身 |
| 产品迭代 | 官网更新日志、媒体报道时间线 | 迭代速度、功能演进方向 |

### 2. 产品技术能力（最难判断，但最关键）

对电商AI客服类产品，用这组问题来判断真假：

| 问题 | 真LLM Agent的特征 | 假LLM/规则引擎的特征 |
|:----|:-----------------|:-------------------|
| 官宣称"AI驱动"还是"LLM驱动"？ | 明确说LLM/大模型 | 说"AI""人工智能"不具体 |
| 多SKU/多面料问题能处理吗？ | "自动学习商品信息、SKU对比" | "需人工配置问答对" |
| 有没有RAG/知识库关键词？ | 提到知识库、自动学习、商品同步 | 只说"关键词匹配""话术库" |
| 部署要多久？ | 30分钟-1小时 | 需要"培训""配置""调试" |

### 3. 定价模式

| 方式 | 优先级 |
|:----|:------:|
| 官网明码标价 | 🥇 最准 |
| 阿里云市场/淘宝服务市场 | 🥈 次之 |
| 行业评测文章 | 🥉 参考 |
| 同类产品区间+品牌定位推算 | 兜底 |

### 4. 营销模式

- **核心渠道**：电商培训机构/代运营合作/大厂生态（这是护城河）
- **话术体系**：提炼核心卖点（将来你用同样的话术框架打它）
- **客户案例**：验证数据真实性（案例通常展示最好成绩）

### 5. 客户情况

- 公开宣称的客户量 → 区分"触达数"和"付费客户数"
- 知名客户名单 → 判断定位（大品牌 vs 中小卖家）
- 案例效果数据 → 独立接待率、节省成本、响应时间

### 6. 财务推算

```
营收 ≈ 付费客户数 × 平均客单价
成本 ≈ 团队规模 × 平均薪资 × 1.5（含社保办公）+ 算力成本
毛利率 ≈ (营收 - 算力成本) / 营收
净利率 ≈ (营收 - 总成本) / 营收
```

IPO前的AI SaaS公司大概率亏损，这决定了它的定价无降价空间。

### 7. 弱点识别（最重要的输出）

从每个维度找弱点：价格太贵？功能太复杂？客户太大？渠道依赖单一？

## 二、输出格式规范

所有竞品分析输出必须：

1. **结构化Markdown表格优先**
2. **有竞品对比矩阵**（价格/技术/功能/客户量列在一起）
3. **有核心结论**（每个竞品一段话）
4. **有自己的机会点分析**（竞品做不到的，你能不能做）
5. **标注信息来源**（可追溯）

## 三、核心原则

1. **扒开营销话术找真相** — "多智能体协同"可能只是规则引擎，用上面的判断矩阵拆穿
2. **价格才是硬道理** — 同技术档次的产品，定价决定市场定位
3. **客户量≠付费客户量** — "服务数万家"可能是累计注册，不是活跃付费
4. **团队规模=烧钱速度** — 50人+团队意味着没有降价空间
5. **渠道壁垒比技术壁垒更难破** — 竞争对手最大护城河可能是渠道关系（如玺承导流）
6. **"真LLM Agent"只有少数** — 电商AI客服赛道，大多数仍是规则引擎+关键词匹配

## 四、常见陷阱 ⚠️

| 陷阱 | 应对 |
|:----|:-----|
| 客户量注水 | 交叉验证多个来源，区分"触达"和"付费" |
| 案例数据选优 | 案例展示最好成绩，不代表平均效果 |
| 定价不透明 | 多渠道推算+标注"推测" |
| 技术夸大 | 用七问判断矩阵拆穿 |
| 财报缺失 | IPO前公司无公开财报，标注"推测" |

## 五、竞品调研Checklist

- [ ] 查工商信息（天眼查/企查查）
- [ ] 查融资历程（投资界/36氪）
- [ ] 扒官网产品页面
- [ ] 找定价信息（官网/服务市场/评测）
- [ ] 找客户案例（官网/新闻/评测）
- [ ] 分析营销话术
- [ ] 判断是真LLM还是规则引擎
- [ ] 估算营收规模
- [ ] 找弱点（至少3个）
- [ ] 写机会点分析（至少3个）
